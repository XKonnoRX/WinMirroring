# WinMirroring

Одно приложение, которое связывает несколько Windows-устройств в единое рабочее место: общий ввод, звук, буфер обмена и файлы, просмотр экрана. Только локальная сеть (и VPN по ручным адресам), без облака и серверов. Архитектура и план этапов: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Состав

| Проект | Что это |
|---|---|
| `src/WinMirroring.Core` | Ядро: идентичность устройства, настройки, выбор интерфейсов, UDP-обнаружение, TLS-транспорт, рукопожатие, сопряжение подтверждением, сессии |
| `src/WinMirroring.Input` | Общие мышь и клавиатура: хуки, сглаживание, переходы через края |
| `src/WinMirroring.Clipboard` | Общий буфер обмена: текст, HTML, RTF, картинки, файлы и папки как виртуальные файлы |
| `src/WinMirroring.Audio` | Передача звука: захват системного звука, Opus по зашифрованному UDP, воспроизведение с буфером |
| `src/WinMirroring.Screen` | Трансляция монитора или окна: Windows.Graphics.Capture, аппаратный H.264 (Media Foundation) или изменившиеся плитки в JPEG, управление из окна просмотра |
| `src/WinMirroring.App` | WPF-приложение в трее: устройства, сопряжение, раскладка, буфер и звук, сеть, настройки |
| `tools/WinMirroring.Cli` | Безголовый узел `wm-cli` для отладки протокола и автотестов |
| `tests/WinMirroring.Core.Tests` | xunit v3: кодеки, криптография сопряжения, интеграция двух узлов на loopback |

## Сборка

Нужен .NET 10 SDK (поставлен через `winget install Microsoft.DotNet.SDK.10`). Visual Studio 2026 открывает `WinMirroring.slnx`.

```powershell
dotnet build WinMirroring.slnx
dotnet test tests/WinMirroring.Core.Tests/WinMirroring.Core.Tests.csproj
dotnet run --project src/WinMirroring.App
```

Тесты идут через Microsoft.Testing.Platform: раннер задан в `global.json` (`test.runner`), без этого `dotnet test` на .NET 10 отказывается работать с xunit v3. Исполняемый файл тестов можно запускать и напрямую из `bin/`.

## Обновление

Скрипт `update.cmd` (рядом `update.ps1` с подробностями) закрывает WinMirroring, копирует новую сборку и запускает его снова с теми же параметрами. Он лежит в репозитории в `scripts/` и в каждой собранной папке.

- **На ноутбуке, из репозитория:** `scripts\update.cmd -Build` собирает новую версию в `artifacts\publish\win-x64-staging` и ставит её туда, откуда запущен WinMirroring (если он не запущен, в `artifacts\publish\win-x64`).
- **На другом устройстве:** скопируйте туда папку новой сборки и запустите `update.cmd` из неё. Обновится та копия, которая сейчас запущена.
- **Из общей папки или архива:** `update.cmd -Source \\НОУТБУК\share\win-x64-staging` или `update.cmd -Source D:\Downloads\WinMirroring.zip`.
- `-Target папка` задаёт, куда ставить, `-NoStart` не запускает после обновления, `-DryRun` только показывает, что будет сделано.

Приложение закрывается так же, как через «Выход» в трее: звук возвращается на динамики, виртуальный монитор убирается. Версии, выпущенные до появления скрипта, этого сигнала не понимают, и скрипт завершает их принудительно; при следующем запуске они сами всё приводят в порядок. Если WinMirroring запущен от имени администратора, обновление тоже нужно запустить от имени администратора. Скрипт не трогает папку, в которой есть файлы, но нет `WinMirroring.exe`.

## Где лежат данные

- Настройки: `%LocalAppData%\WinMirroring\settings.json`
- Журналы приложения: `%LocalAppData%\WinMirroring\logs\`
- Журналы, полученные с других устройств: `%LocalAppData%\WinMirroring\remote-logs\`
- Сертификат устройства: хранилище сертификатов текущего пользователя (`CurrentUser\My`), отпечаток записан в настройках

## Как сопрячь два устройства

1. Запустите приложение на обоих устройствах в одной подсети (или добавьте адрес второго устройства вручную на вкладке «Сеть», если между ними VPN).
2. На первом устройстве выберите второе в списке и нажмите «Сопрячь…».
3. На втором устройстве появится окно с запросом. Нажмите «Принять». Больше ничего вводить не нужно.

Оба устройства показывают одинаковый шестизначный код подтверждения: первое в строке состояния, второе в окне запроса. Код вычисляется из сертификатов обоих устройств. Если коды разные, значит, запрос пришёл не от вашего устройства, и его надо отклонить.

После сопряжения отпечатки сертификатов закреплены, и устройства соединяются автоматически, как только видят друг друга.

Если Windows спросит про брандмауэр, разрешите доступ для частных сетей. Кнопка «Добавить правило брандмауэра…» на вкладке «Сеть» делает то же самое через запрос администратора.

## Общий ввод (мышь и клавиатура)

1. На вкладке «Раскладка» расставьте устройства по сетке 3×3 так, как стоят их экраны, и нажмите «Сохранить раскладку». Раскладка уходит всем сопряжённым устройствам, последняя сохранённая побеждает.
2. Подведите курсор к краю экрана в сторону соседа и надавите на край: курсор появится на соседнем устройстве, клавиатура последует за ним.
3. Назад тем же путём через край, либо Ctrl+Alt+Home, либо кнопка «Вернуть ввод сюда».

Пока курсор на другом устройстве, локальный курсор скрыт, а локальные мышь и клавиатура работают только на удалённое устройство. Если другое устройство перестало отвечать дольше 1,5 секунды, первое же движение мыши или нажатие клавиши возвращает ввод домой.

**Окна администратора.** Windows не пропускает ввод от обычного приложения в окна, запущенные с правами администратора (Диспетчер задач, консоль администратора), и в запросы UAC. Пока такое окно активно на управляемом устройстве, его курсор стоит на месте, но WinMirroring продолжает следить, куда вы ведёте мышь: уведите её через край обратно, и ввод вернётся. Управляющее устройство показывает уведомление, какое окно мешает.

Чтобы управлять и такими окнами, включите на том устройстве галочку **«Управлять окнами администратора через помощника»** на вкладке «Настройки» → «Окна администратора». Тогда отдельная маленькая программа `WinMirroring.InputHost.exe` (она лежит рядом с приложением) запускается с правами администратора и вводит за WinMirroring только мышь, клавиатуру и касания — больше ничего. Само приложение остаётся с обычными правами, поэтому перетаскивание и вставка файлов продолжают работать. Так и задумано в Windows: разные задачи — разные права. Канал между приложением и помощником доступен только вашей учётной записи; приложение проверяет, что подключился именно помощник. Это сознательно открывает вводу с других устройств доступ к окнам администратора, поэтому по умолчанию выключено.

Права администратора Windows спрашивает при включении галочки и пока — при каждом запуске приложения, если галочка оставлена включённой. Автозапуск помощника без запроса (через Планировщик заданий) — следующий шаг. Запуск всего приложения от имени администратора остаётся запасным вариантом в том же разделе, но тогда перестают работать перетаскивание и вставка файлов из обычного Проводника.

**Раскладка клавиатуры.** Клавиши передаются скан-кодами, поэтому буквы зависят от раскладки того устройства, где курсор. Чтобы язык ввода был один и тот же, WinMirroring его синхронизирует. Когда ввод уходит на другое устройство, там включается ваш текущий язык. Если переключить язык уже там (Alt+Shift, Win+Пробел или на панели задач), то после возврата курсора этот язык включится и здесь. Окно просмотра экрана работает так же: пока оно активно и управление включено, на другом устройстве стоит язык этого. Переключается только на языки, добавленные на обоих устройствах. Если нужного нет, устройство покажет уведомление. Список языков каждого устройства виден на вкладке «Настройки» в разделе «Диагностика», отключить синхронизацию можно там же, в разделе «Общий ввод». Окна администратора на управляемом устройстве переключить язык не дают, как и принять ввод.

**Вернуть курсор.** Пункт «Вернуть курсор» в меню значка в трее (и в меню окна просмотра) забирает ввод домой. На управляемом устройстве, например на планшете касанием, он отпускает управление и просит управляющее устройство забрать ввод обратно.

Движение передаётся в пикселях с учётом скорости и ускорения указателя управляющего устройства. На управляемом устройстве адаптивный буфер сглаживает неравномерную доставку пакетов, его текущая величина видна в шапке окна. Настройки буфера на вкладке «Настройки».

Протокол ввода версии 2 несовместим с первой сборкой: обновите приложение на всех устройствах.

## Буфер обмена

Скопированное на любом устройстве попадает в буфер всех сопряжённых устройств, которые сейчас подключены.

- **Текст, HTML, RTF, картинки** передаются сразу. Крупное содержимое, например скриншот, другие устройства подтягивают небольшими частями, чтобы мышь на том же канале не тормозила.
- **Файлы и папки** при копировании не пересылаются. На другом устройстве они появляются в буфере как виртуальные файлы и скачиваются в момент вставки. Explorer показывает свой обычный прогресс копирования.
- **Небольшие наборы файлов**, до 64 МБ по умолчанию, вставляются и в программы, которые понимают только настоящие пути. Такие файлы в момент вставки скачиваются в кэш `%LocalAppData%\WinMirroring\cache\clipboard`, кэш чистится через сутки.
- Исходное устройство помнит восемь последних наборов скопированных файлов. Вставить набор можно, пока его не вытеснили новые копирования файлов, и пока приложение на исходном устройстве запущено.

## Перетаскивание файлов

Начните тянуть файлы или папки в Explorer и, не отпуская кнопку, уведите курсор через край экрана на соседнее устройство. Отпустите кнопку над папкой или окном программы там: файлы скачаются с исходного устройства в момент отпускания. Работает в обе стороны и дальше по цепочке устройств. Если вернуть курсор обратно, не отпуская кнопку, перетаскивание продолжится на исходном устройстве.

Esc во время перетаскивания отменяет его. Выключается флажком на вкладке «Буфер и звук».

## Экран и окна

- **Посмотреть экран другого устройства.** Правая кнопка по устройству на вкладке «Устройства» (или по значку в трее) → «Показать экран». Откроется окно с его монитором. В окне можно управлять мышью и клавиатурой, переключать мониторы, F11 или кнопка «Во весь экран» разворачивает на весь экран.
- **Меню быстрых параметров.** Кнопка «☰ Меню» открывает справа панель с крупными кнопками: полноэкранный режим, закрыть просмотр, управление вкл./выкл., экранная клавиатура, отпустить зажатые там кнопки и клавиши, вернуть курсор общего ввода, куда идёт звук (звук того устройства здесь, звук этого устройства туда или только здесь), монитор, часть изображения, повторная отправка буфера обмена. В полноэкранном режиме панели инструментов нет, вместо неё сверху по центру полупрозрачная кнопка «☰ Меню»: через неё же выходят из полноэкранного режима без клавиатуры. Касание изображения закрывает панель.
- **Касания.** На сенсорном экране касания в окне просмотра передаются как настоящие касания (до 10 пальцев): прокрутка пальцем, масштаб щипком, долгое нажатие работают так же, как на самом устройстве. Мышь остаётся мышью.
- **Экранная клавиатура.** Кнопка «Клавиатура» в панели окна просмотра открывает сенсорную клавиатуру Windows, набранное уходит на другое устройство. Символы, у которых нет обычной клавиши (эмодзи, ввод через IME), передаются как текст.
- **Файлы в окно и из окна.** Перетащите файлы из Explorer на изображение: они будут брошены в ту же точку на другом устройстве, например в открытую там папку. И наоборот: начните тянуть файлы в окне просмотра и уведите курсор за край изображения, не отпуская кнопку, перетаскивание продолжится здесь. Содержимое скачивается в момент броска.
- **Буфер обмена** работает и через окно просмотра: скопированное здесь вставляется там через Ctrl+V в окне просмотра, и наоборот. Кнопка «Отправить буфер» ещё раз отправляет текущее содержимое, если копировали до подключения.
- **Показать одно окно на другом устройстве.** Потяните окно за заголовок и, не отпуская кнопку, уведите курсор через край экрана на соседнее устройство. Там откроется окно с его изображением и управлением, а здесь окно вернётся на место. То же самое делает пункт меню устройства «Отправить окно на это устройство…».
- **Только часть окна или экрана.** В окне просмотра нажмите «Выделить часть» и обведите нужный участок рамкой: передаваться будет только он. «Всё целиком» возвращает полный вид.

### Второй монитор

Экран одного устройства расширяется на другое, как на обычный второй монитор: окна перетаскиваются туда за край экрана и с исходного экрана уходят, на планшете работают касания и экранная клавиатура.

1. На устройстве, чей экран расширяется (например, на ноутбуке), один раз установите открытый драйвер виртуального монитора [Virtual Display Driver](https://github.com/VirtualDrivers/Virtual-Display-Driver) (MIT, подписан), например командой `winget install --id=VirtualDrivers.Virtual-Display-Driver -e` или через его приложение Virtual Driver Control. Перезапустите WinMirroring: на вкладке «Экран» появится «Драйвер виртуального монитора установлен». На планшете драйвер не нужен.
2. На ноутбуке: правая кнопка по планшету → «Использовать как второй монитор» (или меню значка в трее). Или на планшете: правая кнопка по ноутбуку → «Стать вторым монитором этого устройства».
3. Планшет сообщает размер своего экрана и масштаб. Если у драйвера нет такого разрешения, ноутбук один раз попросит права администратора, добавит его в настройки драйвера и перезапустит драйвер (мониторы на секунду мигнут).
4. Виртуальный монитор встаёт с той стороны экрана ноутбука, где планшет стоит в раскладке (по умолчанию справа), с масштабом как на планшете. Планшет показывает его во весь экран.

На планшете «☰ Меню» сверху: свернуть, отключить второй монитор, клавиатура и остальное. Отключить можно и на ноутбуке тем же пунктом меню. Пока режим включён, переход курсора на планшет как на отдельный компьютер выключен: курсор ноутбука просто уходит на второй монитор. Звук ноутбука на второй монитор не переезжает. Когда режим выключается (или WinMirroring закрывается), монитор убирается с рабочего стола, и окна с него возвращаются на экран ноутбука.

Изображение кодируется одним из двух способов, частота кадров сама подстраивается под сеть и скорость отрисовки, по умолчанию не больше 30 кадров/с. **H.264** кодирует весь кадр целиком с аппаратным ускорением видеокарты (NVIDIA / AMD / Intel) — лучше для полноэкранного видео и движущейся картинки. **JPEG** передаёт только изменившиеся участки экрана — почти бесплатно для статичного рабочего стола и окон. На вкладке «Экран» выбор кодека: «Авто» (H.264, когда оба устройства его поддерживают, иначе JPEG), «H.264» или «JPEG», плюс битрейт H.264. H.264 включается, только когда передающее устройство умеет аппаратно кодировать, а принимающее — декодировать; иначе автоматически используется JPEG. Там же можно запретить просмотр и управление этим устройством, а также видно и можно остановить всё, что сейчас показывается другим.

## Звук

По умолчанию звук следует за вводом. Пока ноутбук управляет ПК, звук ПК играет на ноутбуке, а динамики ПК выключены. Когда курсор возвращается, через 2 секунды звук снова играет на самом ПК. Так же звук следует за просмотром экрана: пока планшет смотрит экран ноутбука, звук ноутбука играет на планшете. На вкладке «Буфер и звук» можно закрепить постоянного получателя, выключить приглушение и поменять битрейт и размер буфера.

Когда звук уходит на другое устройство, на отправляющем выключаются **все** активные выходы (а не только устройство по умолчанию), иначе звук, идущий, например, в наушники или на HDMI-монитор, был бы слышен и там, и там. Прежнее состояние каждого выхода запоминается и возвращается, когда звук перестаёт уходить. Если приглушение мешает, его можно выключить галочкой «Приглушать динамики, пока звук играет на другом устройстве».

Вручную в обе стороны, из меню устройства:

- «Слушать звук этого устройства здесь» просит то устройство присылать свой звук сюда (повторный выбор отменяет);
- «Отправлять звук отсюда на это устройство» закрепляет его получателем звука этого устройства (повторный выбор возвращает звук сюда).

Приоритет: закреплённый получатель, затем запросы «слушать здесь», затем управление вводом, затем просмотр экрана.

- Захватывается весь звук системы, кроме самого WinMirroring, поэтому звук, принятый с другого устройства, обратно не уходит.
- Кодек Opus, кадры по 10 мс, по умолчанию 160 кбит/с. Пакеты идут по UDP на порт 47621 и шифруются AES-256-GCM, ключ передаётся внутри TLS-сессии.
- На Windows 10 без поддержки process loopback используется захват всего устройства. Пока такое устройство само играет чужой звук, оно свой не передаёт, чтобы не было эха.

Для приёма звука брандмауэр должен пропускать UDP 47621. Кнопка «Добавить правило брандмауэра…» на вкладке «Сеть» добавляет и его.

## Действия с устройством

Правая кнопка мыши по устройству в списке: управлять им напрямую, показать его экран, отправить туда окно, слушать его звук здесь или отправлять туда свой, проверить задержку через сам канал WinMirroring, открыть ping в консоли, удалённый рабочий стол, сетевую папку, скопировать IP, получить его журнал, переподключить, сопрячь или разорвать сопряжение. Колонка «Задержка» обновляется каждые две секунды.

Меню значка в трее: открыть окно, вернуть курсор, куда идёт звук этого устройства (автоматически, только здесь или всегда на выбранное), слушать здесь звук другого устройства, показать экран устройства.

## Если что-то не работает

- На вкладке «Настройки» в разделе «Диагностика» видно, какие функции запустились на этом устройстве, а какие нет и почему. Если что-то не запустилось, при старте приходит уведомление в трее; остальные функции при этом работают.
- Журнал другого устройства (например, планшета) можно получить, не подходя к нему: правая кнопка по нему → «Получить журнал этого устройства». Файл сохраняется в `remote-logs` и открывается в Explorer.
- Новые возможности окна просмотра (касания, текст, файлы) работают, только если обновлены оба устройства.

## Два узла на одной машине (для отладки)

```powershell
wm-cli --name B --data-dir $env:TEMP\wm-b --loopback --discovery-port 48620 --port 48621 --manual 127.0.0.1:48630 --accept
wm-cli --name A --data-dir $env:TEMP\wm-a --loopback --discovery-port 48630 --port 48631 --manual 127.0.0.1:48620 --pair B --exit-when-ready
```

Порты обнаружения у узлов на одной машине должны отличаться: unicast-зонд доставляется только одному сокету на порт.
