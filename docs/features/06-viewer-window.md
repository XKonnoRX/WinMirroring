# Окно просмотра (ScreenViewerWindow)

> Часть справочника [docs/FEATURES.md](../FEATURES.md). Составлено по коду версии 1.0.75; источник правды — код.

Файлы: `src/WinMirroring.App/Views/ScreenViewerWindow.xaml`, `ScreenViewerWindow.xaml.cs` и партиалы `.Zoom.cs`, `.Detail.cs`, `.Paging.cs`, `.Keyboard.cs`, `.KeyboardButton.cs`, `.Compose.cs`, `.Stats.cs`, `.Still.cs`, `.Surfaces.cs`; `Views/FloatingMenuWindow.xaml(.cs)`; `Services/ButtonBarService.cs`, `IViewerControl.cs`, `SystemTouchGestures.cs`. Окно создаётся в единственном месте — `App.OpenViewerWindow` (`src/WinMirroring.App/App.Viewers.cs`), по событию `ScreenStreamingService.ViewerOpened`. Одно окно на один поток (`ScreenViewer`). Вид потока — `_viewer.Info.Kind`: `"monitor"` (экран), `"window"` (копия одного окна), `"display"` (это устройство — второй монитор другого).

Обозначения: «там» — устройство-источник, «здесь» — устройство с окном просмотра. Все координаты ввода нормализованы 0..1 по картинке (`TryNormalize`, измеряется на `ScreenImage`, поэтому масштаб и сдвиг учитываются сами).

### Режимы окна: с рамкой, во весь экран, копия окна, второй монитор

**Что делает.** Любое окно просмотра открывается сразу во весь экран без панели инструментов: всё управление — в панели плавающей кнопки. F11 выводит из полноэкранного режима в окно с рамкой и панелью инструментов (и обратно). Копия окна (`"window"`) — без рамки, размером ровно с содержимое, появляется у курсора. Второй монитор (`"display"`) — во весь экран, без выбора монитора и рамки-выделения.

**Как устроено.**
- `App.OpenViewerWindow`: `window.Show()` → `OpenFullScreenExternal()` → `BringToFront()`. `OpenFullScreenExternal` ставит `_externalControl = true`, прячет `Toolbar` и `FullScreenHandle`, вызывает `ToggleFullScreen()` (кроме `_windowMode`), снимает `Topmost` — чтобы плавающая кнопка и панель оставались поверх (`App.KeepFloatingOnTop`).
- `ToggleFullScreen` (`ScreenViewerWindow.xaml.cs`): полный экран = `WindowStyle.None` + `WindowState.Maximized` (через Normal), `Toolbar` свёрнут; выход возвращает `_styleBeforeFullScreen`/`_stateBeforeFullScreen` и показывает `Toolbar`. `IsFullScreen => WindowStyle == WindowStyle.None`. Кнопка-ручка `FullScreenHandle` («☰  Меню», справа сверху, непрозрачность 0.55) при `_externalControl` всегда скрывается.
- Панель инструментов (`Toolbar`, видна только в режиме с рамкой): заголовок `TitleText` = «{Info.Title} — {PeerName}»; `MonitorPanel` — «◀» (подсказка «Предыдущий монитор»), «N из M», «▶» («Следующий монитор»), видна при `Kind == "monitor"` и `MonitorCount > 1`; `StatsText` «N кадр/с»; «☰ Меню» (`OnToggleQuickPanel`); «Во весь экран (F11)»; «Клавиатура»; масштаб «−», «100%», «+».
- Копия окна — `PrepareWindowMode`: `_windowMode = true`, `WindowStyle.None`, `ResizeMode.NoResize`, `MinWidth 100`, `MinHeight 80`, `Toolbar` скрыт, включена `DragStrip` — невидимая полоса высотой 34 сверху. Сдвиг мыши с нажатой левой кнопкой > 4 по полосе — `DragMove()` окна; щелчок без сдвига отправляется туда как Left Down+Up в ту же точку (`OnDragStripUp`), то есть кнопки заголовка настоящего окна работают. `PlaceAtCursor` ставит окно в `курсор − (40, 20)`. `SizeToStream` для окон вызывается при каждой смене размера потока и делит пиксели на `Info.ScalePercent/100` источника (не меньше 0.5); для экранов — один раз (`_sizedToContent`), по DPI этого окна, не больше 92 % рабочей области.
- `FollowRemoteWindowState`: копия окна сворачивается вместе с исходным окном (`Info.Minimized`) и возвращается с ним; если пользователь сам развернул копию — туда уходит `WindowCommand.Restore` (`OnViewerStateChanged`).
- Второй монитор — `PrepareDisplayMode`: окно в левом верхнем углу рабочей области, скрыты `ImageHeader`, `QuickMonitorPanel`, `CropToggle`, `ResetCropButton`; `CloseViewerButton` получает текст «Отключить второй монитор»; в `Loaded` включается полный экран, если ещё не включён.
- До первого кадра по центру текст `WaitingText` «Ожидание изображения…».

**Ограничения и запасные пути.** F11 в копии окна проглатывается и ничего не делает. Встроенная быстрая панель (`QuickPanel`) открывается только кнопкой «☰ Меню» на панели инструментов, то есть только в режиме с рамкой после F11; в копии окна (`WindowMenuButton` и `Toolbar` скрыты) она недостижима. В верхних 34 пикселях копии окна туда доходит только левый щелчок: движение, правая кнопка и перетаскивание перехватываются полосой. `BringToFront` из свёрнутого состояния разворачивает экран в `Maximized`, даже если до сворачивания он был в окне с рамкой.

### Плавающая круглая кнопка и её панель

**Что делает.** Круглая кнопка «☰» 46×46 поверх всех окон (подсказка «Меню WinMirroring — нажмите, чтобы открыть; тяните, чтобы переместить»). Нажатие открывает боковую панель, перетаскивание двигает кнопку, место запоминается. В панели для вида, который сейчас впереди: «Управлять» / «Только смотреть» (или пометка «Только просмотр: управление запрещено на том устройстве.»), масштаб «−», «NNN%», «+», «Показатели поверх изображения», «Подвисло — отметить в журнале», для экранов — «Панель кнопок внизу», «Набор «…»», «Настроить кнопки…», затем «Экранная клавиатура», «Закрыть трансляцию» (для второго монитора «Отключить второй монитор»). Выше — «Рабочий стол этого устройства» и остальные открытые виды; ниже у каждого устройства кнопки мониторов с живыми миниатюрами.

**Как устроено.** `FloatingMenuWindow`: без рамки, прозрачное, `Topmost`, `ShowInTaskbar=False`, `ShowActivated=False`, стиль `WS_EX_TOOLWINDOW` (нет в Alt+Tab), исключено из захвата экрана (`CaptureExclusion.Apply` → `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`). Нажатие, пришедшее от устройства, которое смотрит этот экран (`RemoteInputTracker.IsRemote`), игнорируется. Сдвиг > 4 → `DragMove`, затем событие `MovedTo(Left, Top)`; иначе `Clicked` → `App.ToggleControlPanel` (`App.xaml.cs`): `WebWindow` с React-страницей `panel` (`src/WinMirroring.Ui/src/panel/Panel.tsx`), а без WebView2 — `ControlPanelWindow` с тем же набором (без показателей, отметки и миниатюр). Непрозрачность кнопки 0.7, под курсором 1.0.

Панель работает через `IViewerControl` (реализует `App`): `OpenViews` (`OpenViewInfo`: StreamId, Title, PeerId, Kind, MonitorIndex/Count, IsActive, InputAllowed, InputOn, Zoom), `IsLocalDesktopActive`, `ShowLocalDesktop` (сворачивает все виды, кроме копий окон), `SwitchTo`, `CloseView`, `SwitchMonitor`, `ShowOrSwitchScreen` (один вид на устройство: открытый вид переключается на другой монитор вместо второго потока), `ShownMonitorOf`, `ToggleKeyboard`, `SetViewInput`, `ZoomView(+1/−1/0)`, `MarkHitch`, `MonitorPictures`/`WantMonitorPictures`/`MonitorPicturesChanged`. Команды страницы разбирает `PanelUi.RunAsync` (`showLocal`, `switchView`, `closeView`, `keyboard`, `zoom`, `stats`, `mark`, `viewInput`, `showScreen`, `barVisible`, `barPreset`, `editButtons`).

**Настройки.** `AppSettings.MenuButtonX`, `MenuButtonY` (−1: по умолчанию правый край рабочей области − 72, верх + 90), `MenuButtonHidden` (false).

### Встроенная быстрая панель (QuickPanel)

**Что делает.** Правая панель шириной 320 в окне с рамкой; касание картинки закрывает её (`OnSurfacePreviewDown`, нажатие при этом туда не уходит). Пункты:
- «✕» — закрыть панель. Заголовок = заголовок окна.
- ОКНО: «Во весь экран» (переключатель); «Свернуть» (отпускает всё зажатое там и сворачивает); «Закрыть просмотр» / «Отключить второй монитор».
- УПРАВЛЕНИЕ: «Мышь, касания и клавиатура управляют тем устройством» (`ControlToggle`); «Экранная клавиатура»; «Alt+Tab — переключить окно там»; «Отпустить зажатые кнопки и клавиши там»; «Вернуть курсор (общий ввод)».
- ЗВУК: «Звук {устройство} играет здесь»; «Звук этого устройства — на {устройство}»; «Звук этого устройства — только здесь».
- МАСШТАБ: «−», «NNN%», «+» и пояснение «Приближенное изображение двигается двумя пальцами или курсором у края окна. Ctrl+Alt+колесо — приблизить к курсору.»
- ИЗОБРАЖЕНИЕ: «◀», «Монитор N из M», «▶»; «Выделить часть рамкой»; «Показать всё целиком».
- БУФЕР ОБМЕНА: «Отправить буфер обмена ещё раз».

**Как устроено.** `RefreshQuickPanel` при каждом открытии читает состояние звука из `MainViewModel` (`_quick`); без него три переключателя звука скрыты. Кнопка буфера скрыта, если нет `ClipboardSyncService`.

### Управление или только просмотр

**Что делает.** При включённом управлении мышь, касания и клавиши уходят туда; при выключенном остаются здесь, а картинку можно только смотреть и масштабировать.

**Как устроено.** `ControlEnabled => ControlToggle.IsChecked == true && Info.ControlAllowed && CropToggle.IsChecked != true`. Выключение (`OnControlToggleClick`) вызывает `ReleaseRemoteInput`, включение — `ScheduleLayoutPush`. Из панели — `SetInput(on)`: уведомления «Управление {устройство} включено» / «Только просмотр: касания, мышь и клавиши остаются здесь», событие `InputChanged`. Если источник запретил управление (`UpdateInfo`), переключатель и кнопки клавиатуры отключаются, подсказка «Управление запрещено на том устройстве».

**Настройки.** На стороне источника `ScreenSettings.AllowControl` (true).

**Ограничения.** Режим выделения рамкой тоже выключает `ControlEnabled`, пока рамка не нарисована. При запрете со стороны источника `ReleaseRemoteInput` не вызывается: клавиша, зажатая в этот момент, будет отпущена только при потере фокуса окном.

### Мышь и указатель

**Что делает.** Движение, пять кнопок, колесо; Shift+колесо — горизонтальная прокрутка. Указатель того устройства рисуется поверх картинки, свой курсор над ней скрыт.

**Как устроено.** `OnImageMouseMove/Down/Up/Wheel` → `_viewer.SendPointer(PointerAction, button, x, y, delta)`. Нажатие захватывает мышь, кнопка запоминается в `_buttonsDown`; отпускание отправляется только для кнопок, нажатых в этом окне. События мыши, которые WPF сделал из касаний (`IsFromTouch`), пропускаются. Указатель: источник шлёт позицию и форму (`_viewer.Pointer`, `PointerShape`), окно рисует `PointerImage` в `Overlay` (`PlacePointer`); пока мышь здесь над картинкой — по локальной позиции `_pointerHere`, а `ScreenImage.Cursor = Cursors.None`. Перерисовка не чаще одной ожидающей (`DrawPointerSoon`, флаг `_pointerWaiting`); кэш форм `_pointerShapes` до 64.

**Ограничения.** Отдельной обработки пера нет: перо приходит как мышь. На `ScreenImage` отключены `Stylus.IsPressAndHoldEnabled`, `IsFlicksEnabled`, `IsTapFeedbackEnabled`, `IsTouchFeedbackEnabled`.

### Клавиатура

**Что делает.** Клавиши уходят туда по виртуальному коду и скан-коду; символы без клавиши (сенсорная клавиатура, IME, мёртвые клавиши) — текстом. Здесь остаются F11 и Ctrl+Alt с «+», «−», «0». Низкоуровневого перехвата клавиатуры в окне нет: Alt+Tab забирает Windows этого устройства, для него есть кнопка.

**Как устроено.** `OnPreviewKey` (PreviewKeyDown/Up): сначала `ComposeTakesKey`, затем F11, затем `TryZoomWithKey`; далее при `ControlEnabled` — `SyncModifiers` и `_viewer.SendKey(vk, scan, up, extended)`. Модификаторы (`TrackedModifiers`: оба Shift, Ctrl, Alt, Win) не пересылаются как события, а синхронизируются по опросу `Keyboard.IsKeyDown` при каждом событии клавиши — так сочетание не теряет модификатор, зажатый до получения фокуса. Нажатое хранится в `_keysDown`. `Key.ImeProcessed`, `DeadCharProcessed` и клавиши без vk пропускаются и приходят через `OnPreviewTextInput` → `SendText`. Расширенные клавиши — список `ExtendedKeys`.
- «Alt+Tab — переключить окно там» (`OnAltTab`): Alt(0xA4, скан 0x38) вниз, Tab(0x09, скан 0x0F) вниз-вверх, Alt вверх. Без управления — «Включите управление, чтобы отправлять Alt+Tab».
- Отпускание зажатого — `ReleaseRemoteInput`: Up для всех `_buttonsDown`, Cancel для всех `_touches`, key-up для всех `_keysDown`, сброс `_latched`. Вызывается при `Deactivated`, сворачивании, выключении управления, входе в режим рамки, открытии поля диктовки, закрытии окна и кнопкой «Отпустить зажатые кнопки и клавиши там» (уведомление «Кнопки и клавиши на {устройство} отпущены»). Не выполняется во время вытягивания файлов (`_dragOutActive`).
- Раскладка: через 300 мс (`_layoutTimer`) после активации окна, включения управления или смены языка ввода — `InputSharingService.PushKeyboardLayout(peerId, раскладка текущего потока)`; не в режиме второго монитора.

**Настройки.** `InputSettings.SyncKeyboardLayout` (true).

### Касания

**Что делает.** Один палец — настоящее касание там (до 10 одновременных). Два пальца: щипок масштабирует здесь, совместное движение или двойное касание уходят туда. Три пальца, поставленные вместе, — переход между мониторами; остальные жесты тремя пальцами уходят туда. Полная таблица — в конце.

**Как устроено.** `OnImageTouchDown/Move/Up` → `_viewer.SendTouch(действие, контакт, x, y)`: 1 Down, 2 Move, 3 Up, 4 Cancel; `MaxContacts = 10`, номер контакта — наименьший свободный. `_touches` — касания, идущие туда, `_fingers` — их `TouchDevice`, `_gesture` — пальцы локального жеста. Решения принимают `GestureTouchDown/Move/Up` (`ScreenViewerWindow.Zoom.cs`):
- Второй палец, пока первый — касание там (`_touches.Count == 1`): первому отправляется Cancel, оба переходят в `_gesture`. На целой картинке ставится `_undecided`, на приближенной жест сразу локальный.
- «Не решено» (`_undecided`): расстояние между пальцами изменилось на ≥ 12 % (`PinchDecides = 0.12`) — щипок, масштаб здесь; середина сдвинулась на ≥ 28 (`SlideDecides`) раньше — `HandOverToRemote`: оба пальца становятся касаниями там с текущих позиций. Подъём пальца до решения — тоже передача (касание двумя пальцами там). Третий палец до решения — все три туда, если это не начало свайпа.
- Решённый жест: масштаб `start.Zoom × distance / start.Distance` (1..4) с якорем в середине между пальцами; один оставшийся палец двигает картинку. Когда все подняты и масштаб < 1.03 — `ResetZoom`. Третий палец при решённом жесте проглатывается.
- Потеря захвата (`OnImageLostTouchCapture`): в свайпе — `CancelPaging`, в «не решено» — передача туда, для обычного касания — Cancel.

**Ограничения.** При выключенном управлении на целой картинке один палец по-прежнему ничего не значит (WPF делает из него мышь — ею рисуется рамка). С 1.0.77 два пальца там — жест, как везде: окно помнит лежащие пальцы в `_watched`, и второй делает из них щипок (а третий, пришедший вовремя, — свайп между мониторами); в режиме рамки это отключено. До 1.0.77 `GestureTouchDown` возвращал false для любого пальца, и смотрящий не мог ни приблизить щипком, ни перелистнуть монитор. На приближенной картинке без управления один палец двигает её, два — щипок. При включённом управлении на приближенной картинке два пальца всегда локальны — прокрутка двумя пальцами туда не уходит. **На устройстве не проверено.**

### Свайп тремя пальцами между мониторами

**Что делает.** Три пальца вместе и в сторону перелистывают мониторы как страницы: картинка едет за пальцами, а рядом с ней, с той стороны, откуда она уходит, въезжает страница с превью монитора, который там стоит (пальцы влево — монитор справа), и подписью «Монитор N». При отпускании движение доводится: дальше порога — страница плавно доезжает до места и остаётся, пока не придёт первый кадр того монитора; ближе — картинка плавно возвращается. В сторону, где монитора нет, картинка поддаётся неохотно (0,22 движения).

**Как устроено** (`ScreenViewerWindow.Paging.cs`).
- Начало: `JoinsAsThird` — в `_gesture` ровно два пальца, третий пришёл не позже 400 мс после второго (`ThirdFingerWithinMs`, `_twoSince`), `SwipeBetweenMonitors` истинно. Что успели сделать два пальца, откатывается (`_gestureStart.Zoom/Pan`), ставится `_swiping`. После 28 единиц движения середины: `StartsPaging` — `MonitorNeighbours.IsSideways` (|dx| ≥ 2|dy|) и `MonitorRevealedBy(dx)` нашёл соседа → `_paging`; иначе все три пальца передаются туда.
- Сосед — `MonitorNeighbours.Beside` по реальному расположению мониторов (`InputSharingService.PeerMonitors`): ближайший по центру с той стороны, при равенстве — с большим перекрытием по высоте.
- Движение: `SlidePageTo` ставит `_pageShift` (отсчёт от `_pageFrom`, без скачка) и зовёт `ApplyView`; тот в конце зовёт `PlacePage`, который ставит `PageCover` (чёрная страница размером с `Surface`, внутри `PageImage` и подпись `PageLabel`) на `_pageShift ± (ширина + PageGap 24)`.
- Превью: `HavePagePicturesAtHand` → `ScreenViewer.AskForMonitorPictures(640)` — при открытии вида, при смене монитора (`UpdateInfo`) и когда на картинку легли два пальца. Источник шлёт миниатюры несколько секунд и замолкает; окно раскодирует их в `_pagePictures` (`TakePagePictures`) и хранит сам, независимо от того, что панель потом попросит миниатюры убрать. Нет превью (старый источник) — страница чёрная с подписью.
- Отпускание: `FinishPaging` → при |сдвиг| ≥ `CommitsAfter(ширина) = clamp(ширина × 0,12; 90; 260)` и наличии соседа — `SlidePage` до `∓(ширина + 24)`, затем `_pageHeld = ключ` и `GoToMonitor` (сброс рамки и масштаба, `AskForWholeAnew`, `_viewer.SwitchMonitor`); иначе `SlidePage` до 0. `SlidePage` — анимация по `CompositionTarget.Rendering`, кубическое замедление, 140–300 мс в зависимости от расстояния; пока она идёт (`_pageSliding`), новые пальцы игнорируются.
- Страница уходит (`LetThePageGo`, затухание 160 мс): с первым кадром после того, как `Info.MonitorKey` стал её монитором (`PageSawAFrame` из `Present`); через 300 мс после того, как поток назвал этот монитор (`PageHeardOfItsMonitor` — неподвижный экран второго кадра не пришлёт); в любом случае через 2,5 с.
- Потеря захвата касания посреди свайпа — `CancelPaging`: картинка плавно возвращается.

Предупреждение о Windows 11: `WarnIfWindowsTakesTheSwipe` (из `UpdateInfo`) один раз за запуск процесса (`static _saidWindowsTakesThem`) показывает на 14 с: «Свайп тремя пальцами между мониторами перехватывает Windows. Выключите «Жесты тремя и четырьмя пальцами»: Параметры → Bluetooth и устройства → Сенсорный ввод». `SystemTouchGestures.TakeThreeFingers`: есть готовый сенсорный экран (`SM_DIGITIZER`), `SM_MAXIMUMTOUCHES ≥ 3`, сборка ≥ 22000 и `HKCU\Control Panel\Desktop\TouchGestureSetting` отсутствует или не 0.

**Настройки.** `ScreenSettings.SwipeMonitors` (true).

**Ограничения.** Только `Kind == "monitor"` и больше одного монитора; нужен `InputSharingService` и известное расположение мониторов. С 1.0.77 работает и без управления, на целой картинке тоже. Превью — картинка 640 px, растянутая на весь вид: она размыта и может быть старше нескольких секунд. Страница, доведение и превью (1.0.76) **на устройстве не проверены**: собрано и прочитано, жест руками проверяет только владелец.

### Масштаб

**Что делает.** От 100 % до 400 %. Щипок; кнопки «−» / «+» (шаг ×1.25, якорь — центр окна); «NNN%» — показать целиком; Ctrl+Alt+колесо — к курсору (без управления достаточно Ctrl+колесо); Ctrl+Alt+«+»/«−»/«0» — якорь под курсором мыши, а если мыши над картинкой нет, в центре. Приближенную картинку двигает курсор у края окна.

**Как устроено** (`ScreenViewerWindow.Zoom.cs`). `RenderTransform` картинки — `_zoomScale` + `_zoomShift`; состояние `_zoom`, `_pan`, `_lift`, `_pageShift`. Константы `MaxZoom = 4`, `ZoomStep = 1.25`; масштаб < 1.03 округляется до 1. `ZoomTo(zoom, anchor)` сохраняет точку картинки под якорем; `ApplyView` удерживает картинку в окне (`Clamp`: меньше окна — по центру). Кнопки «−»/«+» отключаются на границах (`UpdateZoomText`). Прокрутка у края: `OnSurfacePreviewMouseMove` запускает `_edgeTimer` (16 мс); `EdgePush` — полоса `EdgeBand = 40` от края, скорость до `EdgeSpeed = 22` за тик, линейно; работает при `_zoom > 1`, активном окне и вне режима рамки. После сдвига туда отправляется Move с новой позицией под курсором. После изменения масштаба `ReportShownSize` сообщает источнику размер показа в реальных пикселях (`_viewer.SetShownSize`, шаг 160, 320..7680), также раз в секунду из `_statsTimer`.

### Передача только видимой части при приближении

**Что делает.** При заметном приближении источник кодирует не весь экран, а видимую часть с запасом; она рисуется поверх прежней картинки целого. За краем присланной части на мгновение видна старая, более грубая картинка.

**Как устроено** (`ScreenViewerWindow.Detail.cs`, арифметика — `src/WinMirroring.Screen/ViewParts.cs`).
- Условие: `PartsPossible => !_partsFailed && Info.CropTags && Info.Codec is "h264" or "hevc"` (до 1.0.76 — только `h264`, из-за чего на HEVC части не запрашивались).
- `ViewMoved` (из `ApplyView`) запускает `_partTimer` (40 мс). Часть выбирается, когда вид неподвижен 140 мс (`PartAfterStill`) или движется уже 350 мс (`PartAtLatest`).
- `ChoosePart`: `VisiblePart()` — углы `Surface` в долях картинки; `WantedPart` — `ViewParts.For`: видимое + 15 % с каждой стороны (`Margin`), но если площадь > 0.85 (`WholeAbove`) или `_zoom ≤ 1.02` — целое. Новый запрос не делается, пока `ViewParts.StillServes`: вид внутри запрошенной части, масштаб отличается не более чем на 2 %, с каждой стороны (где есть продолжение картинки) остаётся запас ≥ трети поля.
- `AskFor(part)`: новый номер `_partId` (1..255 по кругу), запись в `_parts`, `_askedPart`, `_askedZoom`; сначала `ReportShownSize`, потом `_viewer.SetCrop(ViewParts.Within(_crop, part), id, part)`. `ScreenViewer` после этого сам пересчитывает координаты ввода в координаты части.
- Каждый кадр несёт `FrameUpdate.CropId`. `Present` → `PartOf(update)`: часть → `PresentDetail` рисует в `DetailImage` и ставит на место через `PlaceDetail`; пустой прямоугольник — кадр отменённой части, отбрасывается; иначе кадр целого, `HideDetail`.
- `AskForWholeAnew` (новая рамка, другой монитор, потеря возможности частей): все прежние номера помечаются `Rect.Empty`, запрашивается целое.
- `ShownSizeFor`: для части — размер × `_askedZoom` × доля части; для целого при возможных частях — не больше `WholeZoomLimit = 1.45`; без частей — размер × `_zoom`.

**Ограничения и запасные пути.** Любое исключение — `GiveUpOnParts`: `_partsFailed = true`, запись в журнал, окно дальше увеличивает целую картинку. При кодеке `"hevc"` и `"jpeg"` части не запрашиваются: источник присылает целое в большем разрешении (не больше собственного).

### Выделение части рамкой

**Что делает.** «Выделить часть рамкой» → уведомление «Обведите рамкой нужную часть изображения» → протянуть рамку мышью (или пальцем на целой картинке). Дальше передаётся только эта часть. «Показать всё целиком» возвращает полный вид.

**Как устроено.** `OnCropToggleClick` отпускает ввод и закрывает панель. `OnImageMouseDown` (левая кнопка) запоминает `_cropStart`, рисует `CropRectangle`; `FinishCrop` снимает переключатель, пересчитывает рамку в доли картинки, отбрасывает меньше 3 % по любой стороне, вкладывает в текущую `_crop` (рамка внутри рамки), затем `AskForWholeAnew`, `ResetZoom`, `ResetCropButton.IsEnabled = true`. `OnResetCrop` возвращает `_crop = (0,0,1,1)`. Кнопки монитора (◀ ▶) и свайп сбрасывают рамку.

**Ограничения.** Слишком маленькая рамка молча отменяется. На приближенной картинке палец в этом режиме двигает картинку, а не рисует рамку. Для второго монитора недоступно; кнопки есть только во встроенной панели.

### Экранная клавиатура

**Что делает.** Открывается кнопкой «Клавиатура» на панели инструментов, «Экранная клавиатура» в обеих панелях, круглой кнопкой ⌨ поверх картинки и, по настройке, сама при касании поля ввода там. Клавиатура ложится поверх окна, а картинка приподнимается так, чтобы место последнего касания осталось видно.

**Как устроено.**
- `TouchKeyboard.Toggle` (`Services/TouchKeyboard.cs`): запускает TabTip.exe при необходимости, COM `ITipInvocation.Toggle`; при ошибке — `osk.exe`. Перед вызовом фокус ставится на `ScreenImage`.
- Положение клавиатуры — `InputPaneWatcher` (`IFrameworkInputPane`): `OnKeyboardShowing` считает подъём: точка интереса `_interest` (последнее нажатие или касание, `NoteInterest`), иначе указатель того устройства; `_lift = clamp(y_точки − (верх клавиатуры − 72), 0, высота перекрытия)` (`KeyboardMargin = 72`); без точки — на всю высоту перекрытия. `OnKeyboardHiding` — `SetLift(0)`.
- `KeepSizeUnderKeyboard` — хук `WM_WINDOWPOSCHANGING`: развёрнутое окно не даёт Windows уменьшить себя под клавиатуру (в полном экране держит прямоугольник монитора, с рамкой — запомненный `_maximizedRect`). Не действует для копии окна.
- Автопоказ (`ScreenViewerWindow.Keyboard.cs`): `_viewer.KeyboardHint(show)` → `OnKeyboardHint`: при `show` и закрытой клавиатуре открывает и ставит `_keyboardFromTap`; при `!show` закрывает только клавиатуру, открытую так.
- Круглая кнопка (`ScreenViewerWindow.KeyboardButton.cs`): `KeyboardHandle` 54×54, непрозрачность 0.6 (1 под курсором и при нажатии). Нажатие — клавиатура; перетаскивание дальше 4 (мышь) или 10 (палец) двигает кнопку. Место хранится долями свободного пространства и сохраняется при отпускании (`_node.SaveSettings()`). Видна при `KeyboardButton != false && !_windowMode && ControlEnabled && HasPicture`; пересчёт раз в секунду.

**Настройки.** `ScreenSettings.AutoKeyboardOnTap` (false), `KeyboardButton` (true), `KeyboardButtonX` (0.97), `KeyboardButtonY` (0.62).

**Ограничения.** `_interest` не сбрасывается — подъём считается от последнего когда-либо нажатого места. Куда уходит набор, если клавиатура открыта из панели плавающей кнопки (фокус у панели), — не выяснено.

### Панель кнопок и наборы под программу

**Что делает.** Полоса кнопок внизу картинки: каждая нажимает там сочетание клавиш и/или набирает текст. Кнопки из одних Ctrl, Shift, Alt — залипающие (подсказка «{название}: держится нажатой, пока не нажмёте снова»). Набор сам меняется под программу, активную там.

**Как устроено.** `ButtonBarService`: `Visible`, `Presets`, `ActiveName`, `PresetNameFor(process)`, `ButtonsFor(process)` — `ButtonPreset.For` берёт первый набор, в `Programs` которого есть имя процесса (без `.exe`, без регистра), иначе выбранный; `ToButton` разбирает `ButtonBinding.Keys` через `KeyChord.TryParseSequence` (нечитаемая кнопка пропускается; ошибка «нет ни клавиш, ни текста»); `SetVisible`, `SetActive`, `SavePresets`, `CopyPresets`, `DefaultPresets`, событие `Changed`. Окно: `RebuildButtonBar` по `Changed` и по `_viewer.ForegroundChanged` (только если сменился набор, `_shownPreset`); `PressBarButton` → `SendChord` (модификаторы, которых ещё нет в `_keysDown`, клавиша вниз-вверх, отпускание в обратном порядке), затем `SendText`. `SetLatch` держит модификаторы в `_latched` и `_keysDown`; модификатор кнопки, исчезнувшей при смене набора, отпускается. Показ: `_bar.Visible && ButtonBarFits && есть кнопки`; `ButtonBarFits` — только `"monitor"` и `"display"`. Уведомления при видимой полосе поднимаются (отступ 72 вместо 24). Без управления: «Только просмотр: включите управление в меню, чтобы кнопки нажимали клавиши там».

**Настройки.** `ButtonBarSettings.Visible` (true), `ActivePreset` («Основные»), `Presets` — по умолчанию «Основные» (Esc, Tab, Win, Alt+Tab, Копировать, Вставить, Отменить, Ctrl, Shift, Закрыть окно), «Браузер» (← Назад, Вперёд →, Обновить, Новая вкладка, Закрыть вкладку, Вернуть вкладку, След. вкладка, Во весь экран), «Текст» (Выделить всё, Копировать, Вырезать, Вставить, Отменить, Повторить, Найти, Сохранить, Enter, ⌫). `ButtonPreset.Programs` (пусто).

### Голосовой ввод и поле набора

**Что делает.** Кнопка 🎤 под кнопкой клавиатуры (или над ней, если снизу нет места) открывает поле поверх картинки и голосовой ввод Windows. Текст из поля уходит туда через 1,3 с после последнего изменения; Enter и «Отправить» — сразу; Esc и «✕» — закрыть без отправки; повторное нажатие 🎤 или касание картинки — отправить и закрыть.

**Как устроено** (`ScreenViewerWindow.Compose.cs`). `ToggleDictation` → `OpenCompose(byVoice: true)`: `ReleaseRemoteInput`, фокус в `ComposeBox`, затем `StartVoiceTyping` нажимает Win+H на этом устройстве через `InputInjector`. `OnComposeChanged` перезапускает `_composeTimer` (`SendAfterPause = 1300 мс`) → `SendComposed(andClose: false)`: `_viewer.SendText`, в конец добавляется пробел. Пока `_composing`, `ComposeTakesKey` забирает все клавиши (не работают и F11, и сочетания масштаба), `OnPreviewTextInput` ничего не пересылает. Подсказка: «Говорите — текст уйдёт на то устройство после паузы. Enter отправляет сразу, Esc закрывает.»; при сбое Win+H — «Не удалось открыть голосовой ввод Windows (Win+H). Текст можно набрать здесь и отправить Enter.». Без управления: «Только просмотр: включите управление в меню, чтобы диктовать на то устройство».

**Настройки.** `ScreenSettings.DictationButton` (true).

**Ограничения.** `OpenCompose(byVoice: false)` нигде не вызывается: поле всегда в голосовом режиме, поэтому и набранный руками текст уходит через 1,3 с паузы, а вторая подсказка («Enter отправляет текст на то устройство, Esc закрывает.») недостижима.

### Показатели и отметка «подвисло»

**Что делает.** Строка в левом верхнем углу вида «N к/с · отклик A мс (здесь V, кодер E) · UDP или TCP · X,X Мбит/с»; при необходимости добавляются «битрейт снижен до N%», «потеряно L, досылок A», «окно не успело B», «через память». Отметка пишет строку в журналы обоих устройств и показывает «Отмечено в журналах обоих устройств».

**Как устроено** (`ScreenViewerWindow.Stats.cs`). `ShowStats` раз в секунду из `_statsTimer`; `StatsLine` берёт кадры, реально нарисованные окном (`_framesSinceTick`), `ScreenStatsMessage` источника и разницу `ScreenViewer.ViewCounts` за секунду. «через память» — `OnCard == 0 && Decoded > 0`. `MarkHitch` → `_viewer.MarkHitch(заметка с масштабом и «whole picture»/«a part»)`.

**Настройки.** `ScreenSettings.ShowStats` (false); переключается пунктом «Показатели поверх изображения».

### Чёткий снимок неподвижного экрана

**Что делает.** Когда экран там замер, поверх видео ложится один резкий снимок; первый же видеокадр его убирает.

**Как устроено** (`ScreenViewerWindow.Still.cs`). `_viewer.StillArrived` → `ShowStill`: отбрасывается, если уже пришёл более новый кадр (`LastFrameNo > AfterFrameNo`), окно ждёт возобновления или снимок относится не к тому, что сейчас нарисовано (целое / та же часть по `CropId`). `StillImage` — слой с `BitmapScalingMode.HighQuality`, место — `PlaceStill`. `HideStill` — в начале каждого `Present` и в `AskForWholeAnew`.

**Настройки.** На источнике `ScreenSettings.SharpStill` (true).

### Отрисовка: с видеокарты или через память, качество масштабирования

**Что делает.** Кадры, декодированные видеокартой, рисуются прямо с неё; иначе — через битмап в памяти. Пока картинка движется, масштабирует видеокарта; когда остановилась — аккуратное масштабирование.

**Как устроено.** `InitializeSurfaces` (`ScreenViewerWindow.Surfaces.cs`): `_viewer.SurfacesWanted = DirectPresent && (RenderCapability.Tier >> 16) >= 2 && Direct3D9Bridge.TryCreate() != null` (один мост на процесс). `ShowWholeSurface`/`ShowPartSurface` → `Draw`: `D3DImage.SetBackBuffer(IDirect3DSurface9, …, enableSoftwareFallback: true)`. Путь через память: `WriteableBitmap` Bgr32 (`_bitmap`, для части `_detail`), запись только изменённых прямоугольников `update.Dirty`. `HasPicture => _bitmap != null || _wholeSurface != null`. Кадры приходят с приоритетом `DispatcherPriority.Input`; в `finally` — `_viewer.FramePresented()`. Качество: `ScaleForMotion` ставит `Linear` и перезапускает `_sharpenTimer` (350 мс, `SharpenAfter`); `ScaleForReading` ставит `HighQuality` — только для картинок в памяти.

**Настройки.** `ScreenSettings.DirectPresent` (true).

**Запасные пути.** Любая ошибка `Draw` → `GiveUpOnSurfaces`: `SurfacesWanted = false`, запись в журнал, следующий кадр приходит в памяти (`WholeArrivedInMemory`). Причина отказа до первого кадра тоже пишется в журнал.

### Переключение мониторов и миниатюры

**Что делает.** «◀» / «▶» в панели инструментов и быстрой панели (по кругу, по номерам), свайп тремя пальцами (по расположению), кнопки мониторов в панели плавающей кнопки — с живыми миниатюрами, пока панель открыта.

**Как устроено.** `SwitchMonitor(step)`: сброс рамки и масштаба, `AskForWholeAnew`, `_viewer.SwitchMonitor((index + step + count) % count)`. Из панели: `IViewerControl.ShowOrSwitchScreen` → `SwitchToMonitor(index, key)` → `GoToMonitor` (тот же путь, что у свайпа: сброс рамки и масштаба). Миниатюры: `PanelUi` раз в секунду вызывает `WantMonitorPictures(панель видна)`; `App.MonitorPictures` отдаёт `ScreenViewer.MonitorPictures` как `data:image/jpeg;base64,…`; обновление страницы не чаще раза в секунду.

**Ограничения.** До 1.0.76 путь из панели не сбрасывал масштаб и запрошенную часть, и касания могли уходить не туда; теперь все три пути идут через `GoToMonitor`.

### Звук, буфер обмена, файлы

**Что делает и как устроено.**
- «Звук {устройство} играет здесь» — `MainViewModel.SetSoundHereAsync(peer, Always | Never)`; уведомления «Звук {устройство} играет здесь», «Звук {устройство} здесь выключен», «Нет связи с {устройство}».
- «Звук этого устройства — на {устройство}» — `SendSoundTo(peerId)` / `SendSoundTo(null)`; «Звук этого устройства играет на {устройство}» / «Звук этого устройства снова следует за вводом и просмотром».
- «Звук этого устройства — только здесь» — `KeepSoundHere()` / `SendSoundTo(null)`; «Звук этого устройства играет только здесь».
- «Отправить буфер обмена ещё раз» — `ClipboardSyncService.PublishNowAsync`; «Буфер обмена отправлен», «Буфер обмена пуст или недоступен», «Буфер обмена не отправлен: …».
- «Вернуть курсор (общий ввод)» — `MainViewModel.ReturnCursor()`, его ответ показывается уведомлением (например «Общий ввод сейчас никуда не передан.»).
- Файлы в окно: `Surface.AllowDrop`; `CanDropFiles` = `DragDropCoordinator.ViewerDragAvailable && ControlEnabled && HasPicture && !_dragOutActive`; `OnSurfaceDrop` → `DropIntoViewerAsync(viewer, paths, x, y)`; «Отпустите файлы на изображении», «Файлы (N) переданы на {устройство}», «Эти файлы нельзя передать», «Не удалось передать файлы: …».
- Файлы из окна: курсор с зажатой левой кнопкой ушёл за картинку дальше 12 (`DragOutMargin`; при приближении — и за край окна) → один раз за выход `DragOutAsync`: `CatchFromViewerAsync`, отпускание кнопки там, `StartViewerDragAsync`; «Перетаскивание с {устройство}: N шт.», «Перетаскивание не удалось: …».

**Настройки.** `ClipboardSettings.DragDropEnabled` (true); звук — свойства `MainViewModel.AudioSendEnabled` и `AudioPinnedTarget` (их запись в `AudioSettings` в этой области не проверялась).

### Уведомления

`ShowNotice(text, seconds = 4)`: жёлтый текст внизу по центру (`NoticeBorder`), следующее заменяет предыдущее, `_noticeTimer` убирает. Все тексты приведены в соответствующих разделах; бессрочное одно — строка ожидания связи.

### Обрыв потока, ожидание и повторное открытие

**Что делает.** Если поток оборвался не по чьей-то воле, окно остаётся с последней картинкой и строкой «Соединение потеряно. Трансляция откроется снова, как только устройство ответит…»; когда устройство отвечает, тот же монитор запрашивается заново и новое окно заменяет старое. Не вернулось — окно закрывается.

**Как устроено.** `OnRemoteClosed`: если `_viewer.CanResume` (`ViewEndings.CanResume`: обрыв связи, причины `"shutdown"`, `"error"`, `"connection…"`) и `WaitToResume(this)` вернул true — `IsWaitingToResume = true`, уведомление без таймера; иначе `Close()`. `App.WaitToResume` (`App.Resume.cs`): только `Kind == "monitor"`; не больше 3 возобновлений за 60 с (`ViewEndings.MostInARow`, `InARowWithin`); запоминает монитор (индекс и ключ) и `InputOn`. `ResumeTick` каждые 500 мс: первый запрос через 700 мс после готовности сессии, повтор каждые 3 с, не более 8 запросов, общий предел 2 минуты (`ResumeWithin`). `TakeOverFromWaiting`: новое окно перенимает `InputOn` и свёрнутость, старое закрывается; лишний ответ на повторённый запрос (в течение 15 с) закрывается без окна.

Автозакрытие неиспользуемого: `App.CloseUnusedViews` каждые 30 с закрывает экран (`"monitor"`), свёрнутый дольше `CloseUnusedViewMinutes`, с системным уведомлением «Трансляция закрыта». `UpdateKeepAwake` не даёт экрану гаснуть, пока хоть один вид виден.

**Настройки.** `ScreenSettings.CloseUnusedViewMinutes` (5; 0 — никогда).

**Ограничения.** Масштаб и рамка при возобновлении не переносятся. Любое обычное уведомление во время ожидания заменит строку о потере связи и через 4 с уберёт её.

### Что запоминается

Между открытиями само окно ничего не сохраняет: ни размер и положение, ни масштаб, ни рамку, ни состояние «управлять / смотреть» (новое окно всегда открывается во весь экран с включённым управлением, если источник его разрешает). В настройках живут: место кнопки клавиатуры (`KeyboardButtonX/Y`), место и скрытость плавающей кнопки (`MenuButtonX/Y`, `MenuButtonHidden`), видимость панели кнопок, выбранный набор и сами наборы (`ButtonBarSettings`), `ShowStats`.
