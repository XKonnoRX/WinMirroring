# Интерфейс: страницы и окна (WinMirroring.Ui, Views)

> Часть справочника [docs/FEATURES.md](../FEATURES.md). Составлено по коду версии 1.0.75; источник правды — код.

Всё ниже подтверждено кодом. Интерфейс двухслойный: React-страницы (`src/WinMirroring.Ui/src`, собираются Vite в `dist`, едут рядом с приложением как `wwwroot`) показываются в `WebWindow` через WebView2; остальные окна — обычный WPF. Если `wwwroot/index.html` рядом с exe нет (`WebWindow.IsAvailable == false`), вместо React-страниц открываются старые WPF-окна `MainWindow` и `ControlPanelWindow`, а функция «Главное окно» в диагностике помечается сбойной («нет собранного интерфейса в …»).

Карта: что чем открывается (`src/WinMirroring.App/App.xaml.cs`):

| Действие | Что открывается |
|---|---|
| Запуск без `--minimized`; левый клик по значку в трее | `ShowHub()` → `WebWindow` с маршрутом `#hub` (вкладка «Устройства») |
| Трей «Открыть WinMirroring»; «Параметры» в панели | `ShowMainWindow()` → `ShowHub()` + push `hub.openSettings` (вкладка «Параметры») |
| Клик по плавающей кнопке (`FloatingMenuWindow.Clicked`) | `ToggleControlPanel()` → `WebWindow` `#panel` (или `ControlPanelWindow`) |
| «Настроить кнопки…» в панели | `ShowButtonEditor()` → `ButtonPresetsWindow` |
| Входящий запрос сопряжения | `DialogPairingUi` → `PairingWindow` |
| «Отправить окно» | `MainViewModel.SendWindowToPeerAsync` → `WindowPickerWindow` |
| «Консоль» / «Консоль администратора» | `MainViewModel.OpenConsoleOn` → `RemoteConsoleWindow` |
| Приём файлов, скачивание/установка обновления | `App.Indicator()` → `FileTransferWindow` |

### Мост страница ↔ приложение (bridge.ts, UiBridge)

**Что это.** Единственный канал между React и C#: запрос-ответ и push-события поверх `window.chrome.webview.postMessage`.

**Как устроено.**
- Файлы: `src/WinMirroring.Ui/src/bridge.ts`, `src/WinMirroring.App/Services/UiBridge.cs`, обработчики — `HubUi.cs`, `PanelUi.cs`, `SettingsUi.cs`.
- Запрос: `invoke(method, args)` шлёт `{id, method, args}` (id — счётчик с 1, `args ?? null`); ответ `{id, ok, result | error}`. При `ok:false` промис отклоняется с `error` (по умолчанию «не получилось»). Неизвестный метод → `нет такого метода: …`. Исключение в обработчике C# уходит на страницу как `error = ex.Message` (и в журнал `UI request failed`).
- Push: C# `UiBridge.Push(name, data)` шлёт `{event, data}` во все подключённые страницы; на странице `on(event, handler)` возвращает функцию отписки. Данных в событиях нет — страница по событию заново запрашивает снимок.
- JSON: camelCase, `null` не опускаются. Все обработчики идут в UI-потоке.
- Методы: `hub.get`, `hub.save`, `hub.command`, `hub.devices` (то же, что `hub.get`; страницей не вызывается), `panel.get`, `panel.command`, `settings.get`, `settings.set`, `settings.command`.
- События: `hub.changed`, `hub.openSettings`, `panel.changed`, `settings.changed`.
- Режим без приложения (`npm run dev`, порт 5183): `inApp == false`, `invoke` обслуживает `mockInvoke` с образцами `sample`, `sampleSettings`, `samplePanel`; в консоли браузера доступен `window.wm.invoke` / `window.wm.push(event, data)`. В образце устройств нет поля `host`, в списке кодеков нет HEVC — это только макет.

### WebWindow (оболочка страниц)

**Что это.** WPF-окно с одним WebView2 на всё окно; показывает `https://winmirroring.local/index.html#<маршрут>`.

**Как открыть.** Создаётся приложением: главное окно (`"hub"`, 1180×800, мин. 720×520, по центру) и боковая панель (`"panel"`, `panel: true`). Оба с `KeepLoaded = true`.

**Элементы.** Текст «Загрузка…» до первой отрисовки; при сбое WebView2 — «Не удалось открыть окно: WebView2 недоступен.».

**Как устроено.** `src/WinMirroring.App/Views/WebWindow.xaml(.cs)`.
- Папка `wwwroot` отображена на виртуальный хост `winmirroring.local` (`SetVirtualHostNameToFolderMapping`); навигация на любой другой адрес отменяется, новые окна запрещены, отключены контекстное меню, зум, свайп-навигация, строка состояния, ускорители браузера.
- Данные WebView2: `%LocalAppData%\WinMirroring\webview`, язык `ru`; среда одна на все окна, прогревается при старте (`WarmUp`).
- `KeepLoaded`: закрытие окна только прячет его (`Hide`), настоящая выгрузка — `CloseForGood()` при выходе. Скрытому окну WebView2 переводится в `Visibility.Hidden`, чтобы страница «уснула» (на это опирается опрос в Panel.tsx через `document.hidden`).
- Режим панели: без рамки, 360 px, `Topmost`, не в панели задач, не забирает фокус, исключено из захвата экрана (`CaptureExclusion`, `WDA_EXCLUDEFROMCAPTURE`); `ShowDocked()` прижимает к правому краю рабочей области на всю её высоту.
- Обычное окно получает тёмный заголовок (`DWMWA_USE_IMMERSIVE_DARK_MODE`).

### Каркас главного окна (main.tsx)

**Что это.** Выбор страницы по `location.hash` и две вкладки главного окна.

**Элементы.**
- Маршруты: `hub`, `layout`, `settings` → `Main`; `panel` → `Panel`; иначе «Нет такой страницы: {route}». Пустой хэш = `hub`.
- Вкладки `Main`: «Устройства» (`<Hub/>`) и «Параметры» (`<Settings/>`). Обе страницы смонтированы постоянно, переключение только скрывает (`hidden`), прокрутка и состояние сохраняются.
- Событие `hub.openSettings` переключает на «Параметры». Маршрут `#settings` сам по себе вкладку «Параметры» не выбирает — начальная вкладка всегда «Устройства».

### Страница «Устройства» — поле раскладки (hub/Hub.tsx, hub/model.ts)

**Что это.** Главный экран: все устройства как группы мониторов в настоящих пропорциях на бесконечном поле; здесь же редактор раскладки (где курсор переходит между устройствами), открытие экранов и вход в действия над устройством.

**Как открыть.** Значок в трее (левый клик), запуск приложения, «Устройства и раскладка…» в панели.

**Элементы.**

| Элемент | Что делает |
|---|---|
| Строка под вкладками `{inputFocus} · {ownSound}` | Где сейчас ввод («Ввод: здесь» / «Ввод: на X (Ctrl+Alt+Home вернёт)») и где играет звук этого устройства |
| «−» (подсказка «Отдалить»), «+» («Приблизить») | Масштаб поля ×1/1.25 и ×1.25 вокруг центра; пределы 0.25–2.5 |
| «По центру» | Вписывает все расставленные устройства в окно (не крупнее 1.6) |
| «Отменить» | Возвращает последнюю сохранённую расстановку; активна только при несохранённых изменениях |
| «Сохранить раскладку» / «Сохраняю…» | `hub.save {placements}` → `InputSharingService.ApplyPlacements`; ответ «Раскладка сохранена и отправлена устройствам.» |
| Поле (фон-сетка из точек) | Перетаскивание пустого места (левая/средняя кнопка) — панорама; колесо — масштаб к курсору (шаг 1.12); два пальца — щипок-масштаб. Клик по пустому месту снимает выбор |
| Карточка устройства | Полоса с точкой связи, именем и метками «здесь» (это устройство), «не на связи», «отдельно» (ни один монитор не касается чужого, при числе устройств > 1). Нажатие без сдвига — выбрать (открывает инспектор); сдвиг больше 3 px мышью / 8 px пальцем — перенос всего устройства |
| Монитор на карточке | Подпись (`ShortLabel`: «Монитор 2 · справа»), размер «1920×1080», отметка основного. Устройство без известных мониторов рисуется одним «Экран» 1920×1080 |
| Кнопка «Показать» / «Показан» на мониторе (подсказка «Показать этот экран здесь») | Только у чужого устройства на связи: `hub.command showScreen {deviceId, monitor: key}` → `IViewerControl.ShowOrSwitchScreen` (уже открытый просмотр переключается на этот монитор, второй поток не создаётся). «Показан» — монитор, открытый сейчас (`shownMonitor`) |
| Светящиеся швы | Участки, где край монитора одного устройства встречается с краем другого (зазор ≤ 48 пикселей поля, `EDGE_TOLERANCE`) — именно там переходит курсор |
| Нижняя строка | «Это устройство не на поле: его курсор никуда не перейдёт.»; ответ последней команды; «Есть несохранённые изменения.»; иначе подсказка про светящиеся края; справа сводка сети (`TCP: …; обнаружение: UDP …`) |

Перенос: при отпускании устройство прилипает к краям соседей (порог 14 экранных px, `settle`) и выталкивается из перекрытий — устройства могут касаться, но не накладываться. Отпускание над лотком (нижние 164 px) убирает устройство с поля. Все перестановки локальны до «Сохранить раскладку».

**Как устроено.**
- `hub.get` → `HubUi.Snapshot`: `self`, `inputFocus`, `ownSound`, `network`, `manualAddresses`, `devices[]` (`id, name, isThisDevice, paired, online, state, address, host, rtt, fingerprint, lastError, version, canUpdate, monitors[], hasVirtualDisplay, sound{here,playing,sentTo}, shownMonitor, introducedBy`), `cells[]` (старая сетка), `placements[]`.
- Координаты: `Placement{deviceId,x,y}` — положение начала рабочего стола устройства в пикселях поля; масштаб отрисовки `SCALE = 0.11`.
- Раскладка старого формата (только `cells`) переводится в расстановку функцией `placementsFromCells`; после сохранения отсюда становится свободной.
- `hub.changed` (смена раскладки, мониторов, фокуса ввода, пиров, сессий, источников экрана, версий, «представлений») → перезагрузка; расстановка на экране заменяется пришедшей, только если у пользователя нет несохранённых правок.
- Мониторы устройства не на связи берутся из запомненных раскладкой (`_input.KeptMonitors`).

### Лоток внизу поля (hub/Tray.tsx)

**Что это.** Полоса внизу поля: сопряжённые устройства вне поля, найденные устройства, ручные адреса.

**Элементы.**
- Заголовок: «Не на поле» / «Все устройства на поле» / во время переноса с поля — «Отпустите здесь, чтобы убрать устройство с поля».
- «+ Добавить устройство вручную» → поле ввода (подсказка «имя или IP, можно host:47620»), «Добавить» (или Enter), «Отмена» (или Esc) → `hub.command addAddress {text}`; адрес пишется в `AppSettings.ManualPeerAddresses`, ответ «… добавлен. Устройство появится, когда ответит…», «… уже в списке.» или «Введите имя или IP устройства.».
- Карточки сопряжённых устройств вне поля (имя; «N монитора» / «это устройство» / состояние) — тянутся на поле.
- «Найдены рядом»: имя + «Сопрячь» → `hub.command pair`.
- «Через другие устройства»: имя, «через {introducedBy}», «Доверять» → `hub.command trust` (сопряжение без подтверждения на двух экранах: отпечаток пришёл от уже доверенного устройства).
- «Адреса вручную»: адрес + «✕» (подсказка «Убрать») → `hub.command removeAddress {text}`.

### Инспектор устройства (hub/Inspector.tsx)

**Что это.** Панель 330 px справа от поля со всем про выбранное устройство.

**Как открыть.** Нажать на устройство на поле или в лотке; «✕» («Закрыть») или клик по пустому полю закрывает.

**Элементы.** Шапка: имя, точка связи, состояние, задержка (`rtt`). Красный блок `lastError`, если есть. Дальше один из четырёх видов:

1. Не сопряжено, есть `introducedBy`: пояснение, «Отпечаток», «Доверять» (`trust`).
2. Не сопряжено: «Устройство найдено в сети, но ещё не сопряжено…», «Сопрячь» (`pair`).
3. Это устройство: только текст «Это устройство. Перетащите его на поле…».
4. Сопряжённое чужое устройство — таблица ниже (всё через `hub.command {name, deviceId, text}`).

| Раздел | Кнопка | Команда → что происходит | Когда недоступна |
|---|---|---|---|
| — | «Показать экран» | `showScreen` без монитора → монитор с индексом 0 | не на связи |
| — | «Управлять вводом» | `controlInput` → `InputSharingService.ControlPeer`; «Ввод передан на X. Вернуть: Ctrl+Alt+Home.» | не на связи |
| — | «Разбудить по сети» (на всю строку) | `wake` → пакет пробуждения на MAC устройства; «Пакет пробуждения для X отправлен (…)» | кнопки нет вовсе, пока устройство на связи или его MAC неизвестен (`canWake`) |
| Инструменты | «Сетевая папка» | `openShare` → проверка SMB, вход, открытие `\\host` (`NetworkShare`) | нет `host` |
| | «Открыть файл там…» | `openOnDevice` → системный диалог «Что открыть на X» (несколько файлов) → `PeerFilesService.OpenOnDeviceAsync` | не на связи |
| | «Консоль» | `console` → `RemoteConsoleWindow` | не на связи |
| | «Консоль администратора» | `consoleElevated` → то же с `elevated: true` | не на связи |
| | «Рабочий стол (RDP)» | `remoteDesktop` → `mstsc.exe /v:host` | нет `host` |
| | «Копировать IP» | `copyAddress` → адрес в буфер | нет `host` |
| | «Проверить задержку» | `latency` → 20 запросов по сессии с шагом 50 мс; среднее/мин/макс/разброс/потери | не на связи |
| | «Ping в консоли» | `ping` → `cmd.exe /k ping -t host` | нет `host` |
| | «Забрать журнал» | `peerLog` → журнал сохраняется, Проводник открывается с выделенным файлом | не на связи |
| | «Переподключить» | `reconnect` → сессия закрывается, с сопряжённым восстанавливается сама | не на связи |
| Окна и мониторы | «Отправить окно» | `sendWindow` → `WindowPickerWindow` | не на связи |
| | «Сделать вторым монитором» | `secondMonitor` → переключатель: расширить рабочий стол на то устройство / прекратить | не на связи |
| | «Стать его вторым монитором» | `becomeSecondMonitor`; при `hasVirtualDisplay === false` кнопки нет, вместо неё пояснение про драйвер | не на связи |
| Звук {имя} здесь | «Авто» / «Всегда» / «Никогда» | `soundHere` c `text` = `auto`/`always`/`never` → `AudioService.SetIncomingChoiceAsync`; под ними «Сейчас играет здесь.», если играет | — |
| Звук этого устройства | «Туда» / «Авто» / «Здесь» | `soundTo` c `pin`/`auto`/`here`: закрепить получателя (`AudioSettings.PinnedTargetId`), вернуть автомат, выключить отправку (`SendEnabled = false`) | — |
| Устройство | «Обновить отсюда» | `updateDevice` → `PeerFilesService.SendOwnBuildAsync`; только при `canUpdate` | — |
| | Факты «Версия», «Адрес», «Отпечаток» | только чтение | — |
| | «Убрать с поля» | локально убирает с поля (до сохранения); только если устройство на поле | — |
| | «Разорвать сопряжение» | `unpair` → системный вопрос «Разорвать сопряжение с X? Для повторного подключения понадобится новый PIN.» → `MirroringNode.UnpairAsync` | — |

Без `host` под инструментами показывается «Адрес этого устройства пока неизвестен…».

**Как устроено.** `HubUi.RunAsync`. Перед `controlInput`, `secondMonitor`, `becomeSecondMonitor`, `updateDevice`, `reconnect`, `removeAddress` вызывается `RemoteGuard` (см. ниже); отказ → «Отменено.». Команда `pair` ждёт завершения `MirroringNode.PairAsync` (до 2 минут) и только потом возвращает «Запрос на сопряжение отправлен на X.»; сам код подтверждения на запрашивающем устройстве приходит уведомлением трея и в `StatusText` (нижняя строка «Параметров»).

### Сопряжение (PairingWindow, DialogPairingUi)

**Что это.** Подтверждение входящего запроса на сопряжение. Вводить ничего не надо: сертификаты уже проверены рукопожатием, окно только закрепляет их.

**Как открыть.** Само, на устройстве, которое получило запрос (`PeerSession.HandlePairRequestAsync` → `IPairingUserInterface.ConfirmIncomingPairingAsync`).

**Элементы.** Окно «WinMirroring — сопряжение», 440 px, поверх всех, модальное:
- заголовок «{имя} хочет сопрячься с этим устройством»;
- текст «Если сопряжение начали вы на {имя}, нажмите «Принять»…»;
- «Код подтверждения (тот же, что на другом устройстве)» — шесть цифр в виде `123 456`;
- отпечатки «Другое устройство:» и «Это устройство:»;
- «Принять» (по умолчанию, Enter) и «Отклонить» (Esc).

**Как устроено.**
- `src/WinMirroring.App/Views/PairingWindow.xaml(.cs)`, `src/WinMirroring.App/Services/DialogPairingUi.cs`, `src/WinMirroring.Core/Pairing/PairingCrypto.cs`.
- Код: SHA-256 от строки-домена `WinMirroring-confirmation-v1` и двух отпечатков (в верхнем регистре, отсортированных), первые 4 байта по модулю 1 000 000 — одинаков на обеих сторонах независимо от того, кто спросил.
- Тайм-аут `ProtocolConstants.PairingTimeout` = 2 минуты: по истечении окно закрывается с отказом.
- На запрашивающей стороне окна нет: `PairingStarted` даёт текст «Подтвердите сопряжение на X. Код на обоих устройствах: NNN NNN» в `StatusText` и уведомлением трея; `PairingFinished` — «Сопряжение с X выполнено.» либо «…не выполнено (причина)»; причины: «отклонено на другом устройстве», «отменено», «на другом устройстве не ответили за две минуты», «другое устройство сейчас не может сопрягаться», «соединение потеряно».
- Третий путь — «Доверять» (`Introductions.TrustAsync`), без окна.

### Боковая панель / быстрое меню (panel/Panel.tsx)

**Что это.** Панель 360 px у правого края поверх всего: что сейчас на экране, устройства, ввод, прочее. Единственное место управления полноэкранным просмотром (у него в полноэкранном режиме нет своей панели).

**Как открыть.** Клик по плавающей кнопке; повторный клик или «✕» закрывает. Пункты, выбирающие экран или открывающие окно, закрывают панель сами.

**Элементы** (все через `panel.command {name, screenX, screenY, …}`):

| Раздел | Пункт | Команда и действие |
|---|---|---|
| Шапка | «WinMirroring», «✕» | `close` |
| На экране (только если есть открытые просмотры) | «Рабочий стол этого устройства» | Если активен — строка «● …»; иначе кнопка `showLocal`: полноэкранные просмотры сворачиваются |
| | Неактивный просмотр — кнопка с названием «{устройство}: {заголовок}» | `switchView {streamId}` |

### Защита от нажатия с другого устройства (RemoteGuard)

**Что это.** Окно-вопрос перед действием, после которого до устройства можно не дотянуться.

**Как открыть.** Само, если нажатие «скорее всего удалённое»: `RemoteInputTracker.ActiveWithin(4000 мс)` или `InputSharingService.IsBeingControlled`. Сидящего за устройством не спрашивают.

**Элементы.** Окно «WinMirroring — подтверждение» по центру монитора под курсором: вопрос, объяснение, строка «Нажатие пришло с другого устройства… Без ответа через 30 секунд будет «Отмена».», кнопки «Отмена» (по умолчанию) и красная «Да, …» (включается через 1 секунду).

**Как устроено.** `src/WinMirroring.App/Services/RemoteGuard.cs`. Спрашиваются: `settings.set` — `screen.allowControl` и `screen.allowViewing` при выключении, `input.enabled` при выключении, `input.adminControl` при включении; `settings.command` — `applyNetwork`, `addFirewall`, `adminNoPrompt`, `adminPrompt`, `restartElevated`, `installVirtualDisplay`, `stopSource`; `hub.command` — `controlInput`, `secondMonitor`, `becomeSecondMonitor`, `updateDevice`, `reconnect`, `removeAddress`; «Выход» в меню трея. Переключатели ввода в боковой панели (`panel.command`) через RemoteGuard не идут — удалённые нажатия по панели отбрасываются целиком.

### Редактор кнопок трансляции (ButtonPresetsWindow)

**Что это.** Редактор наборов кнопок, которые показываются внизу полноэкранного просмотра и нажимают клавиши / набирают текст на просматриваемом устройстве. Работает на копии; до сохранения ничего не меняется.

**Как открыть.** Панель → «Настроить кнопки…» (в старой панели «Настроить кнопки и наборы…»). Одно окно; повторный вызов активирует открытое.

| «Удалить» | С вопросом «Удалить набор «имя»?» |
| «Название» | Имя набора |
| «Для программ» | Имена процессов через запятую/пробел/точку с запятой, «.exe» необязателен → `ButtonPreset.Programs`. Пока одна из программ активна на просматриваемом устройстве, показывается этот набор; пусто — только вручную |
| «+ активная сейчас» | Дописывает процесс, активный сейчас там (`Viewer.ForegroundProcess`); если неизвестен — «Сейчас не открыт экран другого устройства, или оно ещё не сказало, какая программа активна.» |
| «Кнопки (слева направо)» (список) | Строки вида «подпись — клавиши + «текст»», « (залипает)» для залипающих, «⚠» для нечитаемых |
| «+ Кнопка», «Удалить», «↑» («Левее»), «↓» («Правее») | Добавить после выбранной (подпись «Кнопка»), удалить, сдвинуть |
| «Подпись» | Текст на кнопке |
| «Клавиши» + «Записать» | Строка аккордов («Ctrl+Shift+T»; несколько через запятую: «Ctrl+K, Ctrl+C»). «Записать»: следующее нажатое сочетание попадает в поле; один отпущенный модификатор записывается как залипающая кнопка; подпись «Кнопка» заменяется сочетанием |
| «Текст (необязательно)» | Набирается там после клавиш |
| Строка под редактором | «Нажмёт там: …», «Залипающая: … держится там, пока не нажмёте её снова.», «Наберёт там текст.» или «Эта кнопка не появится: {причина}.» |
| «Добавить стандартные наборы» | Добавляет «Основные», «Браузер», «Текст» (под уникальными именами) |
| «Сохранить и показать этот набор» | Проверки: у каждого набора есть имя, имена не повторяются, все кнопки читаются; затем `ButtonBarService.SavePresets` и закрытие |
| «Отмена» | Закрыть без сохранения |

**Как устроено.** `src/WinMirroring.App/Views/ButtonPresetsWindow.xaml(.cs)`, `src/WinMirroring.App/Services/ButtonBarService.cs`, `src/WinMirroring.Core/Settings/ButtonBarSettings.cs`. Хранение: `ButtonBarSettings.Visible` (вкл), `ActivePreset` («Основные»), `Presets` (три стандартных набора). Залипает кнопка из одних Ctrl/Shift/Alt без текста; одиночный Win — обычное нажатие. Выбор набора по программе: `ButtonPreset.For` — первый набор, назвавший процесс, иначе выбранный вручную. Настройки кнопок не синхронизируются между устройствами.

### Передача файлов и обновления: индикатор (FileTransferWindow)

**Что это.** Маленькое окно прогресса в правом нижнем углу рабочей области (отступ 16 px); не берёт фокус, поверх всех, исключено из захвата экрана.

**Как открыть.** Само: `ClipboardSyncService.TransferProgress` (приём файлов при вставке/перетаскивании) и ход обновления (`App.ShowProgress`).

**Элементы.** Заголовок («Передача файлов» → «Файлы получены» / «Передача не удалась»; для обновления «Обновление {тег}» → «Обновление скачано» / «Обновление не скачалось» / «Обновление готово»), строка «что», полоса, строка «{сделано} из {всего} · NN% · {скорость}/с · ещё m:ss». По завершении «Готово» или «Ошибка».

**Как устроено.** `src/WinMirroring.App/Views/FileTransferWindow.xaml(.cs)`. Скорость считается по окну последних 4 секунд и показывается после 0.7 с; при неизвестном размере полоса неопределённая. Скрывается само через 2 с после успеха и через 5 с после ошибки. Единицы: Б, КБ, МБ, ГБ, ТБ.

### Консоль устройства (RemoteConsoleWindow)

**Что это.** Командная строка на другом устройстве поверх уже установленной сессии: строка туда, вывод обратно по мере появления. Не терминал — интерактивные и «рисующие экран» программы не работают.

**Как открыть.** Инспектор → «Консоль» или «Консоль администратора» (`ShellService.Open(peerId, elevated)`; без готовой сессии — «Консоль на X не открыть: нет готового соединения.»).

**Элементы.** Окно «Консоль: {имя}», 860×520:
- слева вверху текущий каталог на том устройстве; справа состояние: «Запрашиваю разрешение…», «Ждём человека за устройством», «Выполняется…», «Отказано», «Устройство пропало», «Консоль закрыта»;
- «Прервать» — доступна во время выполнения; завершает оболочку там, консоль закрывается;
- вывод: только чтение, выделяется и копируется; строки stderr с префиксом «! »; ненулевой код — «[код выхода N]»; команда отображается как «> команда»;
- поле команды и «Выполнить» (Enter); стрелки вверх/вниз — история введённого в этом окне.

**Как устроено.** `src/WinMirroring.App/Views/RemoteConsoleWindow.xaml(.cs)`; события `RemoteConsole`: `Opened`, `Refused`, `Asking`, `Lost`, `Output`, `Done`, `Finished`. Одна команда за раз (поле блокируется до `Done`). Буфер вывода 400 000 символов, при переполнении отрезается первая половина. При отказе со словом «выключено» выводится подсказка, где включить на том устройстве. Закрытие окна закрывает консоль. На принимающей стороне нужны `ShellSettings.AllowCommands` (и `AllowElevatedCommands`), подтверждение — системным окном «Да/Нет» (`shell.Confirm` в `App.xaml.cs`).

### Выбор окна для отправки (WindowPickerWindow)

**Что это.** Модальный список окон этого устройства, которые можно показать на другом.

**Как открыть.** «Отправить окно» в инспекторе или панели.

**Элементы.** Окно «WinMirroring — отправить окно», 520×480: заголовок «Какое окно показать на {имя}?», пояснение, список заголовков (`ScreenStreamingService.ShareableWindows()`, выбрана первая строка), «Отправить» (Enter, двойной щелчок), «Отмена» (Esc).

**Как устроено.** `src/WinMirroring.App/Views/WindowPickerWindow.xaml(.cs)`, вызов в `MainViewModel.Screen.cs`. После выбора — `TransferWindowAsync`; если общий ввод включён и окно ушло не на «второй монитор», ввод передаётся туда же («Управление ушло туда же.»).

### Старая боковая панель (ControlPanelWindow)

**Что это.** WPF-вариант боковой панели; используется только когда нет `wwwroot`.

**Как открыть.** Плавающая кнопка при `WebWindow.IsAvailable == false`.

**Элементы.** Те же разделы «НА ЭКРАНЕ», «УСТРОЙСТВА», «ВВОД», «ПРОЧЕЕ», что в Panel.tsx, с отличиями:
- есть раздел «ЗВУК»: «Автоматически» / «Только здесь», «Всегда на {имя}», для каждого устройства «Звук {имя} здесь» с пояснением и «Авто / Всегда / Никогда»;
- под именем устройства строка версий («Версия 1.0.12 · здесь 1.0.13»), кнопка «Обновить до {версия}»;
- мониторы — текстом «Основной экран (подпись)», «Монитор N (подпись)», « — открыт»; без миниатюр;
- «Использовать как второй монитор» показан только при установленном здесь драйвере виртуального монитора; если драйвера нет на другом устройстве, вместо «Стать вторым монитором этого устройства» выводится строка «Стать вторым монитором: на X нет драйвера виртуального монитора»;
- нет пунктов «Показатели поверх изображения» и «Подвисло — отметить в журнале»; «Открыть файл на устройстве…», «Настроить кнопки и наборы…» названы иначе.

**Как устроено.** `src/WinMirroring.App/Views/ControlPanelWindow.xaml(.cs)`. Перестраивается целиком по таймеру 400 мс, когда изменилась строка-подпись состояния (`BuildSignature`), и один раз через 2.5 с после нажатия. Нажатия с удалённого устройства игнорируются и закрывают панель.

### Старое окно с вкладками (MainWindow)

**Что это.** Прежнее WPF-окно настроек (920×640) с привязкой к `MainViewModel`; запасной вариант без `wwwroot`. Закрытие прячет окно.

**Как открыть.** `App.ShowOldSettings()` — только если React-интерфейс не собран.

**Элементы.** Шапка (имя, отпечаток, сеть, фокус ввода, сглаживание, идентификатор), строка состояния и вкладки:
- «Устройства»: таблица (Имя, Состояние, Задержка, Адрес, Сопряжено, Отпечаток, Последняя ошибка), «Сопрячь…», «Разорвать сопряжение», контекстное меню («Управлять этим устройством», «Показать экран», «Отправить окно на это устройство…», «Использовать как второй монитор (вкл./выкл.)», «Стать вторым монитором этого устройства», «Слушать звук этого устройства здесь (вкл./выкл.)», «Отправлять звук отсюда на это устройство (вкл./выкл.)», «Проверить задержку», «Ping в консоли», «Удалённый рабочий стол (RDP)», «Открыть сетевую папку», «Копировать IP-адрес», «Получить журнал этого устройства», «Переподключить», «Сопрячь…», «Разорвать сопряжение»);
- «Раскладка»: сетка 4×3 ячеек с выпадающим списком (устройство целиком или отдельный монитор), «Открыть поле раскладки» (`App.ShowHub`), «Сохранить раскладку» (`InputSharingService.ApplyLayout`), «Вернуть ввод сюда», подпись про Ctrl+Alt+Home;
- «Буфер и звук», «Экран», «Сеть» (здесь есть «Удалить» для ручного адреса), «Настройки» — те же настройки, что на странице «Параметры», но без: экономии заряда, раздела «Команды», переключателей свайпа, показателей, прямой отрисовки, кнопок клавиатуры/диктовки, авто-клавиатуры, чёткого кадра, закрытия свёрнутого экрана, установки драйвера и задания планировщика.

**Как устроено.** `src/WinMirroring.App/Views/MainWindow.xaml(.cs)`, команды в `MainViewModel*.cs`.

### Значок в трее и системные диалоги

- Значок (`App.CreateTrayIcon`): левый клик — окно устройств. Меню перестраивается при каждом открытии: «Открыть WinMirroring», «Вернуть курсор», «Вернуть окна на место», «Показать кнопку меню», «Звук этого устройства» → («Автоматически: за вводом и просмотром», «Только здесь», «Всегда на {имя}»), при наличии устройств на связи — «Слушать здесь звук устройства», «Показать экран устройства», «Использовать как второй монитор», «Стать вторым монитором для» (подменю по устройствам), «Выход» (через RemoteGuard).
- Плавающая кнопка: положение `AppSettings.MenuButtonX/Y` (−1 — правый край, 90 px от верха рабочей области), скрытие `MenuButtonHidden`.
- Системные окна «Да/Нет»: разрыв сопряжения, удаление набора кнопок, разрешение консоли, приём файлов/обновления с другого устройства. Системный диалог выбора файлов — «Открыть файл там…».
- Уведомления трея: сопряжение, обновления, второй монитор, окна администратора, закрытие неиспользуемой трансляции, сбой функций при запуске.

### Визуальная система (theme.css)

`src/WinMirroring.Ui/src/theme.css` — только тёмная тема на CSS-переменных: фоны `--bg-deep #090b0f` … `--surface-hover #232b37`, текст `--text / --text-dim / --text-faint`, один акцент `--accent #5b6cff` со свечением, статусы `--good / --warn / --bad`, скругления 14/9 px, общая кривая `--ease`. Шрифт Segoe UI Variable, 15 px. Общие классы: `.btn` (мин. высота 42 px под палец; `.btn-accent`, `.btn-ghost`, `.btn-icon`), `.chip`, `.dot`/`.dot-on`, `.row`, `.hint`, `.field`, `.switch`, `.section`, `.shell*`. Выделение текста и системные жесты страницы отключены (`user-select: none`, `touch-action: none`); учитывается `prefers-reduced-motion`. Стили страниц: `hub/Hub.css`, `panel/Panel.css`, `settings/Settings.css`. WPF-окна оформлены отдельно (тёмные `#1F2937`/`#111827` у панели, индикатора, консоли и вопроса RemoteGuard; остальные — стандартные светлые).

### Настройки без элемента в интерфейсе

- `AppSettings.PinConnectionsToInterface` (вкл), `AppSettings.FindPeersOnTailscale` (вкл) — только в файле настроек.
- `AudioSettings.FollowScreenViewer` (вкл) — переключателя нет ни в React, ни в старом окне.
- Служебные, меняются не через формы: `AppSettings.DeviceId`, `CertificateThumbprint`, `PairedPeers`, `MenuButtonX/Y` (перетаскивание кнопки), `MenuButtonHidden` (пункт панели / трея); `InputSettings.LayoutVersion`, `LayoutOrigin`, `Layout`, `Placements` (поле раскладки); `ScreenSettings.KeyboardButtonX/Y` (перетаскивание кнопки в просмотре); `AudioSettings.MutedByApp`; `ButtonBarSettings.*` (панель и редактор кнопок).
- Команда `settings.command returnHome` и метод `hub.devices` на стороне C# есть, страница их не вызывает.
