# WinMirroring: справочник по функциям

Что умеет приложение и где это в коде. Составлен по коду версии 1.0.75 (ноябрь 2026): каждый раздел написан после чтения соответствующих файлов целиком, не по памяти и не по README. Все упомянутые в разделах пути и идентификаторы сверены с репозиторием автоматически, выборка констант — вручную; поведение запуском не проверялось, если в разделе не сказано иное.

Три документа делят работу так:

- `README.md` — для пользователя: как поставить и как пользоваться.
- `docs/ARCHITECTURE.md` — почему сделано так: решения и заметки по выпускам в порядке появления. Ранние его части местами устарели (см. «Расхождения» ниже).
- `docs/FEATURES.md` и `docs/features/*.md` — что есть сейчас: каждая функция, её механизм, настройки, сообщения, ограничения и тесты. **Источник правды — код; если справочник с ним расходится, прав код, а справочник надо поправить.**

**Правило сопровождения.** Изменение, которое добавляет, убирает или меняет функцию, настройку, сообщение протокола, жест или кнопку, правит соответствующий файл в `docs/features/` в том же коммите. Перед работой над областью сначала читается её файл — он короче кода и говорит, что там уже есть.

## Расхождения и находки

Собрано при составлении справочника. Это не список задач: решать, что из этого чинить, — отдельно.

### Ошибки, подтверждённые по коду

1. **HEVC: при приближении не включается «только видимая часть».** `ScreenViewerWindow.Detail.cs`: `PartsPossible` требует `Info.Codec == "h264"`, а поток HEVC объявляет `"hevc"`. На HEVC увеличивается целая картинка. (Появилось в 1.0.75.)
2. **HEVC: после отступления на H.264 картинки может не быть.** `ScreenViewer`: если декодера HEVC на устройстве нет (не декодируется видеокартой), ставится `_videoDecodeUnavailable`, и приход ключевого кадра уже в H.264 его не сбрасывает — сброс стоит только в ветке «декодер есть, но другого формата». (Появилось в 1.0.75; HEVC выключен по умолчанию.)
3. **«Применить» в «Параметры → Сеть» откатывает адреса, добавленные вручную.** `MainViewModel.ApplyNetworkAsync` пишет `settings.ManualPeerAddresses = ManualAddresses.ToList()`, а эта коллекция заполняется при запуске; команды моста `addAddress` / `removeAddress` (`HubUi`) правят настройки напрямую и её не обновляют.
4. **Смена монитора из панели плавающей кнопки не сбрасывает масштаб и запрошенную часть.** `ScreenViewerWindow.SwitchToMonitor` вызывает только `_viewer.SwitchMonitor`; кнопки ◀ ▶ и свайп идут через `GoToMonitor`, который сбрасывает всё. При активной части координаты касаний и мыши могут уходить не туда, пока вид не сдвинется.
5. **Без управления («только смотреть») на целой картинке не работают ни щипок, ни свайп тремя пальцами.** `GestureTouchDown` при выключенном управлении и масштабе 100 % возвращает `false` для любого пальца.

### Похоже на ошибку (по чтению кода, запуском не проверено)

- `ScreenViewer`: у обычным образом закрытого окна просмотра не освобождаются таймер 1 мс (`MediaTimerResolution.Hold`) и шифры — окно зовёт только `Close()`, а служба вызывает `DisposeAsync` лишь для видов, ещё числящихся в `_viewers` (05).
- Смена монитора теряет ограничение кадров на батарее: `SwitchMonitor` шлёт `ScreenRequestMessage` без `MaxFps` (05).
- После отступления видеопотока на плитки `VideoLink` остаётся в состоянии `Carrying`: показатели пишут «UDP», хотя плитки идут по TCP (04).
- `ScaleBitrate` ограничивает битрейт площадью 1080p: картинка 1440p или 4K получает столько же, сколько 1080p (04).
- Автообновление: переключатель `AutoUpdate` действует только после перезапуска; скачанное обновление ставится на следующем тике таймера (6 ч) или вручную, а не «когда устройство свободно»; результат `GithubUpdater.Apply` не проверяется; архив не сверяется ни по хэшу, ни по подписи; скачанные архивы в `%TEMP%` не удаляются (07).
- Возобновление вида: при живой сессии, но молчащем источнике окно ожидания закрывается после 8 запросов (около 24 с), а не через две минуты (07).
- Выключение `AllowViewing` не останавливает уже идущие трансляции; выключение `AllowCommands` не закрывает открытые консоли (05, 09).
- `Input.Enabled = false` выключает только роль управляющего: управлять этим устройством через край по-прежнему можно (02).
- Устройство без сессии, переставшее слать маяки, остаётся в списке навсегда: `PeerDirectory.Remove` никто не вызывает (01).
- Приоритет трафика: видео помечается тем же классом, что и звук, хотя задумано «звук впереди экрана» (01).
- Гонка в знакомстве по цепочке: если прямое соединение установится раньше `vouch-relay`, только что созданная запись о сопряжении может быть удалена (01).
- Испорченный `settings.json` молча заменяется новым: новое имя устройства, новый сертификат, сопряжения потеряны (01).
- Удалённая консоль: строка вывода длиннее 8192 байт обрезается до 2730 символов; `exit N` в команде даёт код 65 без сообщения; хвост слишком длинного сценария может выполниться; литерал в `ElevatedShellHost.cs` сохранён в двойной кодировке и уходит мусором (09).
- Буфер обмена: `OfferPrefetcher` никто не освобождает — брошенная вставка может оставить индикатор прогресса; входящие изменения применяются каждое в своей задаче, и большое может лечь поверх более нового маленького; отказ принять файлы отправитель узнаёт только для трёх типов ошибок, иначе ждёт 15 минут (03).
- Числовая настройка вне допустимого диапазона молча не сохраняется, но страница продолжает показывать введённое (07, 08).
- Выпуск: CI не запускает тесты и не сверяет тег с `<Version>`; `wm-cli` в архив выпуска не входит (09).

### Где документы отстали от кода

- **README: «по умолчанию не больше 30 кадров/с».** `ScreenSettings.MaxFps` по умолчанию 60; 30 — это `PowerSettings.Fps` в режиме экономии.
- README и ARCHITECTURE называют запуск помощника администратора без запроса UAC «следующим шагом» — он есть (`ElevatedHelperTask`, кнопки «Выдать права один раз» / «Спрашивать права снова»).
- README описывает вкладки старого `MainWindow` и окно просмотра «с рамкой, F11 — во весь экран». Сейчас «Параметры» — вкладка React-окна, а окно просмотра открывается сразу во весь экран, F11 выводит в режим с рамкой. Кнопка «☰ Меню» сверху по центру в полном экране не показывается.
- README: поле набора «можно набрать руками и отправить целиком» — по коду набранное тоже уходит через 1,3 с паузы.
- README ничего не говорит об автообновлении с GitHub, разрешениях удалённой консоли, режиме экономии, `wm-cli --exec`.
- ARCHITECTURE §4–5: `ScreenCapabilityMessage` (на деле `DeviceCapabilitiesMessage`), «TLS 1.3» (версию выбирает ОС), отдельное соединение на файл (на деле канал `File` той же сессии), проект `WinMirroring.Files` (нет), «курсор рисует WGC» (указатель передаётся отдельно), окно из двух неподтверждённых кадров (три), Raw Input как источник движения мыши (только для упора в край), сетка как движок раскладки (свободное поле), перо через `InjectSyntheticPointerInput` (такого кода нет), настраиваемые горячие клавиши (есть только Ctrl+Alt+Home), «40 тестов».
- В комментариях кода осталось «PIN pairing» (PIN нет, есть «Принять» и шестизначный код для сверки); XML-комментарий `ScreenCodec` описывает старую раскладку кадров.

### Настройки, которых нет в интерфейсе

`AppSettings.PinConnectionsToInterface`, `AppSettings.FindPeersOnTailscale`, `AudioSettings.FollowScreenViewer` — только в файле настроек. В «Параметры → Сеть → Адреса вручную» адрес можно добавить, но убрать — только из лотка на странице устройств.

### Чего нет вовсе

Передачи микрофона, пера как пера (приходит как мышь), работы на экране блокировки и на защищённом рабочем столе UAC, выбора звукового устройства, истории буфера обмена, PTY в удалённой консоли (это не терминал: нет ввода в работающую программу и изменения размера).
